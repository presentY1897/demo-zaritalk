## ✅ 기반 결정 (2026-08-31, grill-me 세션 확정)

이후 모든 task의 전제가 되는 결정들.

**스택·구조**

- Next.js 풀스택(Prisma + PostgreSQL). 프론트는 공고 스택 그대로 — TS·Tanstack Query·Jotai·PandaCSS·pnpm
- TurboRepo 모노레포 — `apps/web`(모바일 웹, 앱 웹뷰 가정) + `apps/admin`(데스크톱 백오피스) + `packages/db·ui·config`
- 계정 모델: 1계정 다중 프로필(User→Profile 1:N, 유형별 1개) — 임대인·세입자·중개인·마스터 전환식. ADMIN은 `User.isAdmin` 별도
- 도메인: Building → Unit → Lease 3계층 — 계약·매물·민원·작업은 호실(Unit) 단위
- 마스터 = 인테리어·청소 등 협력업체(업종+활동반경 프로필). 임대인 작업 의뢰에 견적 제안 → 수락 매칭, 세입자 민원의 작업 전환으로 연결
- 금액 단위: 원(KRW) Int — 실거래가만 API 원본 단위인 만원

**기능 방식**

- 인증: 전화번호 + 모의 OTP(데모용 코드 노출) + 역할별 원클릭 데모 로그인
- 수납: 매월 청구 자동 생성 + 수동 체크 + **가상 입금 시뮬레이션**(실입금 확인 불가하므로), 부분납부·미납 이월·연체료까지 원장 수준
- 고지서: 알림톡 시뮬레이터(발송 로그) + 토큰 기반 공개 고지서 페이지 + 하단 가입 유도 CTA
- 세입자 연결: 가입 시 전화번호 매칭 → 세입자 수락 단계
- 중개 매칭: 중개인 활동지역(좌표+반경) 기반, 공실 반경 내 거리순 최대 20명
- 매물 탐색: 카카오맵 지도+리스트 하이브리드
- 통근시간: 카카오모빌리티(차량)+ODsay(대중교통) 실연동, (매물,근무지) 캐시 → 목록 배지
- 자리페이: 토스페이먼츠 테스트모드 실연동, 결제 성공 시 수납 원장 자동 반영
- 환급: 세액공제 계산기(5년 소급) + 신청(서류 업로드) + 백오피스 심사 큐
- 실거래가: 국토부 공공데이터 실연동(배치 수집+캐시) + 알림 구독
- 커뮤니티: 지역별 보드 + 인기글 + 신고 → 백오피스 모더레이션
- 그로스: 자체 이벤트 트래킹 + A/B 플래그 1개 실운영 + 백오피스 퍼널 차트, 공개 페이지 SEO
- 배포: Vercel + Neon Postgres + GitHub Actions CI
- 범위: **1차** 수납·고지·장부 / 매물·중개·통근 / 자리페이·환급 / 커뮤니티·실거래가 / 민원·마스터, **2차** 실거주 리뷰·임대차계약신고, **제외** 단기임대. 일정 제약 없음, 완성도 우선

## ⏳ D1. API 스타일

- **제안**: REST형 Route Handlers로 통일(Server Actions 미사용), zod 4로 요청·응답 검증.
- **대안**: 변경(mutation)은 Server Actions, 조회는 Route Handlers 혼용.
- **트레이드오프**:
  - Route Handlers 통일 — Tanstack Query 훅과 1:1로 맞아떨어지고, "앱 웹뷰가 소비하는 API"라는 데모 서사가 명확. API 표면이 코드로 드러나 포트폴리오 리뷰에 유리.
  - Server Actions 혼용 — 폼 제출 코드가 간결하고 타입이 직결되지만, Query 캐시 무효화를 수동 관리해야 하고 API 계층이 데모에서 안 보임.
- **추천**: Route Handlers 통일.

## ⏳ D4. 마스터 매칭 방식

- **제안**: **pull 피드** — 마스터가 자기 업종+활동반경 내 REQUESTED 의뢰를 피드로 조회하고 견적 제안(T5.2).
- **대안**: **push 타겟팅** — 중개 매칭(T3.6)처럼 의뢰 생성 시 대상 업체를 선정해 발송(타겟 테이블 필요 → 스키마 추가).
- **근거**: 업체가 일감을 찾아다니는 실제 UX에 부합하고, 중개 매칭(push)과 패턴이 달라져 데모에 매칭 패턴 2종을 보여줄 수 있음. 현재 스키마도 pull 기준(타겟 테이블 없음).
- **추천**: pull 피드.
