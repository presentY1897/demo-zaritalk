# T1.8 공개 고지서 페이지 (그로스 핵심)

> Phase 1 · 상태: ✅ · [Phase 구성](../PHASES.md)

| 라우트/API | 동작 |
|---|---|
| `/notice/[token]` | **비로그인 공개** — 청구 내역 상세, 납부 계좌 안내(더미), 임대인 메시지, 하단 「자리톡으로 월세 관리하기」 가입 CTA([D2](../DECISIONS.md#-d2-ab-실험-소재-1개-실운영) A/B 대상), OG·SEO 메타 |
| `GET /api/notices/[token]` | 공개 데이터, **첫 조회만 `openedAt` 기록** + `notice_view` 트래킹 |

**미가입 세입자에게 도달하는 유일한 접점**이다(D2). 이 페이지의 CTA 가 그대로 가입 퍼널의 입구다.

## 공개 라우트 위치 — `(app)/notice/[token]` 과 그 이유

```
app/
├─ (app)/                     ← 480px 셸 + (프로필이 있으면) 하단 탭바
│  ├─ page.tsx                `/` 랜딩(비로그인 허용)
│  ├─ search/                 `/search` (T3.2, 비로그인 허용)
│  ├─ notice/[token]/         `/notice/<token>` ← **여기** (T1.8, 비로그인 허용)
│  └─ (protected)/            ← layout 이 requireUser() → 비로그인이면 /login
└─ (auth)/                    로그인·온보딩 전용(탭바 없음)
```

- 로그인 강제는 `(app)/(protected)/layout.tsx` **한 곳**이 한다([T0.5](./t0.5-shell-profile.md)).
  그 그룹 **밖**, `(app)` 바로 아래에 두면 480px 셸은 그대로 쓰면서 로그인은 걸리지 않는다 —
  T0.5 가 `/search`·`/refund/calculator` 와 함께 이 경로를 그렇게 두기로 이미 정해 뒀고, 그 계획을 그대로 따랐다.
- `(auth)` 안에 두면 안 된다 — 거기는 로그인·온보딩 전용 레이아웃이다.
- 비로그인 방문자에게는 **탭바가 그려지지 않는다**(`AppShell` 은 프로필이 없으면 탭바를 뺀다).
  그래서 미가입자가 보는 화면에는 고지서와 CTA만 남는다.
- E2E 가 "비로그인으로 열리는가"를 직접 지킨다(`/api/me` 401 + `/login` 리다이렉트 없음).

## 렌더링 — 서버 렌더 + 브라우저에서만 남기는 열람 기록

내용은 **서버 렌더**다. 카카오톡·슬랙 링크 미리보기와 검색 크롤러가 JS 없이 읽어야 하고,
미가입 세입자가 첫 화면을 기다리지 않아야 한다.

반대로 **열람 기록과 `notice_view` 는 브라우저에서만** 남긴다 —
`NoticeOpenTracker`(클라이언트) → `GET /api/notices/[token]`.

- 링크 미리보기 봇은 JS 를 돌리지 않으므로 **봇이 "열람"으로 잡히지 않는다.**
  임대인 이력의 "열람"이 사람의 열람을 뜻해야 하기 때문이다.
- `notice_view` 를 클라이언트 `useTrack()` 이 아니라 **서버(같은 요청)에서 적재**한 이유도 같다 —
  열람 기록과 조회 이벤트가 한 번의 요청에서 함께 나와야 둘이 어긋나지 않는다.
  anonId 는 `POST /api/track`(T0.7)과 **같은 규칙**으로 ① 쿠키 ② 서버 발급 순으로 정하고,
  쿠키가 없었으면 응답에 `Set-Cookie` 로 심는다. 그래서 이후 클릭·가입 이벤트와 **같은 anonId** 로 이어진다.
- 중복 호출은 `useQuery`(`staleTime: Infinity`)가 막는다(StrictMode 이중 effect·리렌더).

### `openedAt` 은 최초 1회만

```ts
// features/notice/queries.ts
await prisma.messageLog.updateMany({ where: { token, openedAt: null }, data: { openedAt } });
```

조건부 갱신이라 동시에 두 번 열려도 한 번만 찍힌다. 재조회로 갱신되면 "언제 처음 봤는지"를 잃는다.
응답의 `firstOpen` 이 이번 조회가 최초였는지를 알려 준다.

## CTA variant 구조 — T6.1 이 붙을 자리

문구·배치 원본은 `features/notice/cta.ts` **한 곳**이다.

| variant | placement | 문구 |
|---|---|---|
| `A` (대조군·기본) | `bottom` — 고지서를 다 읽은 뒤 하단 카드 | "자리톡으로 월세 관리하기" / "고지서·납부 내역·계약 정보를 한곳에서…" |
| `B` | `top` — **금액 위 배너 한 줄 + 하단 카드** | "이 고지서, 내 계약에 연결할까요?" / "가입하면 이번 달 고지서부터 지난 납부 내역까지…" |

```ts
export const NOTICE_CTA_EXPERIMENT = "notice_cta";       // AbAssignment.experimentKey 와 같은 값
export type NoticeCtaVariant = "A" | "B";
export const NOTICE_CTA_CONTENT: Record<NoticeCtaVariant, NoticeCtaContent>;
export function resolveNoticeCtaVariant(value?: string | null): NoticeCtaVariant;   // 모르면 A
export function noticeCtaHref(token: string, variant: NoticeCtaVariant): string;
```

```ts
// 지금 — app/(app)/notice/[token]/page.tsx (딱 이 한 줄이 배정 지점이다)
const variant = resolveNoticeCtaVariant(variantParam);          // ?variant=B 로 데모·E2E 확인

// T6.1 — anonId 배정으로 갈아 끼운다. 화면·이벤트 코드는 한 줄도 바뀌지 않는다
const variant = await assignVariant(anonId, NOTICE_CTA_EXPERIMENT);
```

`NoticeCta` 는 `variant` prop 만 보고 문구·배치를 바꾸고, 클릭 이벤트에는 항상
`props: { experiment, variant, placement, slot, token }` 이 실린다. `GET /api/notices/[token]?variant=B`
로 넘긴 값은 `notice_view` 의 `props.variant` 에도 남으므로 **노출/클릭을 변형별로 셀 수 있다**.

## CTA → 가입 퍼널을 어떻게 이었나

CTA 는 `/login?from=notice&notice=<token>&experiment=notice_cta&variant=<A|B>` 로 보낸다.

1. **anonId 로 잇는다(본선)** — `zari_anon` 1st-party 쿠키(T0.7)가 고지서 → 로그인 → 온보딩까지
   같은 값으로 유지되므로, 퍼널 4단계가 **한 방문자로 묶인다**. E2E 가 이 anonId 로 순서를 검증한다.
2. **쿼리로 출처를 남긴다(보조)** — `page_view` 는 쿼리까지 포함한 경로를 기록하므로
   (`lib/tracking/page-view.tsx`), 로그인·가입 이벤트의 `path` 에 "어느 고지서·어느 변형에서 왔는지"가 남는다.
   로그인 화면(T0.4 소유)은 이 값을 읽지 않는다 — **그 파일을 건드리지 않고 출처를 잇기 위한 선택**이다.
3. 클릭 시 `flush()` 로 큐를 즉시 비운다 — 화면 전환 중 이벤트가 유실되지 않게.

> 로그인 화면이 나중에 이 쿼리를 읽으면(예: "고지서에서 오셨네요" 배너, 번호 미리 채우기) 전환율을 더 올릴 수 있다.
> T6.1·T6.4 가 손댈 자리로 남겨 둔다.

## OG·SEO 메타

`generateMetadata`(Next 16 — `params` 는 Promise)에서 채운다. `metadata` 객체와 함께 쓸 수 없으므로 함수만 둔다.

| 항목 | 값 |
|---|---|
| `title` | `행당해피빌 202호 8월 월세 고지서 — 자리 데모` |
| `description` | `납부하실 금액 580,000원 · 납부기한 2026.08.25 · 김임대 임대인` (만기 안내는 만기일 기준) |
| `openGraph` | `type: article` · `siteName` · `locale: ko_KR` · `url: /notice/<token>` · 같은 title·description |
| `twitter` | `card: summary` |
| **`robots`** | **`{ index: false, follow: false }`** |
| `metadataBase` | `NEXT_PUBLIC_WEB_URL`(없으면 localhost) — 상대 URL 을 절대 URL 로 만든다 |

- **검색 색인은 일부러 막았다.** 이 페이지에는 이름·호실·금액 같은 개인정보가 있다.
  OG 는 카카오톡·슬랙 링크 미리보기용으로 채우고(공유가 곧 유입이다), 색인 대상은 매물·커뮤니티(T6.4)로 둔다.
- 없는 토큰이면 메타도 "고지서를 찾을 수 없습니다" + `noindex` 로 내려간다.
- `metadata`·`generateMetadata` 는 서버 컴포넌트 전용이라 CTA·트래커만 클라이언트로 내렸다.
- OG 이미지는 두지 않았다(정적 자산이 없다). T6.4 에서 `opengraph-image` 로 붙이면 된다.

**최소(Vitest, 7)** — `app/api/notices/[token]/route.test.ts`
- **없는 토큰·형식이 아닌 토큰 404**(이벤트도 남지 않는다)
