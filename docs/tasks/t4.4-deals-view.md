## `/deals` 는 **공개**다 — 왜 `(protected)` 가 아닌가

화면은 `apps/web/src/app/(app)/deals/page.tsx`(보호 그룹 **밖**)에 있고 `GET /api/deals` 도 비로그인 200 이다.
반대로 **구독은 로그인 필수**(401)이고 온보딩 전 계정은 403 이다.

1. **개인정보가 한 줄도 없다.** 국토부 실거래가는 공개 데이터이고, 이 화면이 그리는 값은 누가 보든 똑같다.
   로그인으로 가릴 것이 없다. (T4.1 커뮤니티를 로그인 뒤에 둔 이유 — "참여가 전부 프로필을 요구한다" — 가 여기엔 없다.)
2. **유입 화면이다.** T3.2 `/search`(비로그인 매물 탐색)·T2.3 `/refund/calculator` 와 같은 자리다.
   먼저 값을 보여 주고 **개인화가 필요한 순간(알림 구독)에만 로그인**을 요구한다 —
   T2.3 계산기(공개) → T2.4 신청(로그인)과 같은 층 나눔이다.
3. 로그인을 세우면 A/B·SEO(T6.4)로 이 화면을 쓸 수 없고, 나중에 여는 것보다 **지금 열어 두는 편이 되돌리기 싸다**
   (닫는 것은 폴더 한 칸 옮기면 되지만, 열려면 조회 함수의 시점 처리를 다시 봐야 한다).

**T0.5 가 못 박은 비로그인 화면 셋**(`/search`·`/refund/calculator`·`/notice/[token]`)에 `/deals` 가 없는 것은
그때 이 화면이 탭 배정표에 아예 없었기 때문이다. 탭 목적지가 아니라 **새로 여는 공개 경로**라 그 목록과 충돌하지 않는다.

> **탭바에는 넣지 않았다** — 탭 구성표(`features/shell/tabs.ts`)는 T0.5 소유라 이 task 가 건드리지 않는다.
> 지금은 `/deals` URL 로 들어온다. 탭·링크를 붙이는 것은 T0.5(탭 조정)나 T6.4(SEO 진입점) 몫이다.

### 온디맨드 수집이 공개 경로에 열려 있는 것은 괜찮은가

`GET /api/deals` 는 **그 지역에 수집분이 한 줄도 없을 때만** 국토부를 부른다. 요청 공간이 셋으로 닫혀 있어서다:

- 지역은 **T4.1 상수표의 35개**뿐(그 밖은 400), 월은 최근 3개월 고정 → 도달 가능한 조합이 유한하다.
- 같은 지역은 **쿨다운 10분**(실패해도 찍는다) 안에서 다시 부르지 않는다.
- **커서를 들고 오는 요청은 트리거하지 않는다**(이미 목록을 보고 있다는 뜻이다).

즉 최악이라도 10분에 35지역 × 3개월 × 2엔드포인트다. 쿨다운·진행 표시는 프로세스 메모리라 인스턴스가 여러 개면
인스턴스 수만큼 늘 수 있다(수집 자체는 멱등이라 데이터는 어긋나지 않는다).

## 캐시 우선 — DB 가 캐시다

우리 `RealTransaction` 이 곧 캐시이고, 조회는 항상 DB 를 먼저 본다.

| 상황 | `sync.reason` | 무엇을 하나 |
|---|---|---|
| 그 지역에 수집분이 있다 | `CACHE_HIT` | 국토부를 부르지 않는다 |
| 비어 있고 키가 있다 | `SYNCED` | 최근 3개월을 긁어 오고 목록에 담는다 |
| 비어 있는데 최근에 시도했다 | `COOLDOWN` | 부르지 않는다 |
| 서버에 키가 없다 | `NO_KEY` | 부르지 않는다 |
| 불렀는데 실패했다 | `FAILED` | **200 + 빈 목록**으로 화면은 그대로 뜬다 |

실거래가는 하루에 몇 건 늘어나는 값이라 분 단위 신선도가 의미 없다. 매일 도는 크론(T4.3)이 당월·전월을 계속
채우므로 화면은 캐시를 읽는 것으로 충분하고, 온디맨드는 "처음 열어 본 지역이 텅 비어 있는" 것만 막는다.

## 커서 페이지네이션 — **정의는 한 곳뿐이다**

원본은 `apps/web/src/features/deals/cursor.ts` 이고 단위 테스트(`cursor.test.ts`)와 API 테스트가 지킨다.
규약의 모양은 T4.1 커뮤니티와 같다.

| 정렬 | 커서에 담기는 값 |
|---|---|
| `dealDate DESC, id DESC` (최신 거래순, 하나뿐) | `lawdCd` · `dealType` · `dealDate` · `id` |

- **마지막 보조 키는 언제나 `id`** 다. `dealDate` 는 `@db.Date` 라 같은 날 거래가 수십 건씩 동점이고,
  유니크 키로 닫지 않으면 페이지 경계에서 한 줄이 두 번 나오거나 사라진다.
- 커서에는 정렬 이름 대신 **지역·유형**을 싣는다 — 여기서는 정렬이 하나뿐이고 대신 그 둘이 화면의 탭이다.
  성동구 전세 커서를 강남구 매매 탭에 쓰면 조건이 어긋나므로 **400** 이다. 깨진 커서도 400 이다
  (조용히 첫 페이지로 되돌리면 무한 스크롤이 같은 자리를 맴돈다).
- 커서는 `base64url("<lawdCd>|<dealType>|<dealDateMs>|<id>")` — 불투명 문자열이라 클라이언트가 파싱해 쓸 수 없다.
- `take: limit + 1` 로 한 줄 더 읽어 다음 페이지 유무를 판단하고, 마지막으로 **내보낸** 행으로 다음 커서를 만든다.

정렬 키가 **변하지 않는 값**(거래일·id)이라 커뮤니티 인기 탭 같은 "읽는 도중 순서가 바뀌는" 한계가 여기엔 없다.

## 알림 매칭 규칙 — **정의는 한 곳뿐이다**

원본은 `apps/web/src/features/deals/alerts.ts` 의 `alertMatches` 이고, `alerts.test.ts` 가 조합 표 전체를 지킨다.
`TransactionAlert` 는 세 칸짜리 구독이다: `lawdCd`(필수) · `aptName`(선택) · `dealType`(선택).
**선택 칸이 비어 있으면 "전부"** 라는 뜻이고, 세 칸은 **AND** 로 걸린다.

| 구독 | 뜻 | 매칭 |
|---|---|---|
| `11200 / null / null` | 성동구 전부 | 성동구의 모든 신규 거래 |
| `11200 / null / JEONSE` | 성동구 전세만 | 지역 + 유형 |
| `11200 / 신금호파크자이 / null` | 그 단지 전부 | 지역 + 단지 |
| `11200 / 신금호파크자이 / WOLSE` | 그 단지 월세만 | 셋 다 |

### 단지명은 **공백을 지운 뒤 완전일치**다

부분일치(`includes`)로 하면 "자이" 구독이 "래미안자이"·"자이르네" 까지 잡아 알림이 시끄러워지고, 무엇이 잡힐지
사용자가 예측할 수 없다. 그래서 완전일치로 두되 **공백만 무시**한다(`e편한세상 금호파크힐스` ↔ `e편한세상금호파크힐스`).
대신 구독 시트는 자유 입력이 아니라 **그 지역·유형에서 실제로 수집된 단지 목록에서 고르게** 한다 —
그래서 "골랐는데 안 온다" 가 생기지 않는다.

### 알림은 **구독 1건 × 수집 실행 1회 = MessageLog 1건**

한 번 수집에 그 단지 거래가 12건 새로 들어와도 알림톡은 한 줄이다(본문에 최근 3건 + "외 N건").
거래마다 보내면 지역 전체 구독자 한 명에게 수백 건이 쌓인다 — 시뮬레이터라도 그건 거짓말이다.
**새로 저장된 것이 없으면 알림도 없다** — 그래서 크론이 매일 돌아도 같은 알림이 다시 가지 않는다.
`MessageKind` 에 실거래가 전용 값이 없어 `ETC` 를 쓴다(T2.5 환급 통지와 같은 사정).

### 구독 유니크는 **애플리케이션이 보장한다**

스키마에 `@@unique([profileId, lawdCd, aptName, dealType])` 가 있지만, `aptName`·`dealType` 이 nullable 이고
**Postgres 기본 유니크 인덱스는 NULL 을 서로 다른 값으로 본다**(`NULLS DISTINCT`). 그래서 가장 흔한 구독인
"지역 전체"(`aptName`·`dealType` 둘 다 NULL)가 **몇 번이고 다시 만들어진다.**
스키마는 이 task 소유가 아니라, `features/deals/subscriptions.ts` 가 **advisory 락**(`pg_advisory_xact_lock`)으로
구독 키를 잠근 뒤 "있으면 그것을 돌려주고 없을 때만 만든다"(`duplicated: true`). 계정당 상한은 20개다.

### 쓰기는 활성 프로필, 소유는 계정

만들 때 주인은 **활성 프로필**(T0.5 쿠키)이지만 목록·삭제는 **그 계정의 모든 프로필**을 본다 —
세입자 프로필로 걸어 둔 알림을 임대인으로 바꾼 뒤에도 지울 수 있어야 한다(T4.1 이 정리한 규칙 그대로).

## 화면

| 조각 | 동작 |
|---|---|
| 시군구 셀렉트 | **T4.1 상수표 재사용**(서울 25개 구 + 경기 10개 시). 지역을 바꾸면 검색어·단지 선택이 초기화된다 |

| 단지 검색 | 부분일치로 목록을 좁힌다. 카드의 단지명을 누르면 **완전일치 + 추이 차트**로 바뀐다 |
| 무한 스크롤 | 목록 끝 `IntersectionObserver` + **「더 보기」 버튼**(키보드·스크린리더·E2E 가 쓰는 확실한 경로) |
| 알림 시트 | 비로그인이면 로그인 링크만. 로그인이면 단지·유형 셀렉트 + 구독 목록(해제 버튼) |

지역·유형·검색·단지는 `history.replaceState` 로 **주소에만** 반영해 네비게이션 없이 스크롤·읽은 페이지를 유지하고,
새로고침·공유하면 서버 컴포넌트가 그 값으로 첫 페이지를 그린다(`?lawdCd=&type=&q=&apt=`).

## API 요청·응답

에러는 전부 `{ "error": { "code", "message", "details?" } }` 한 형태다([D1](../DECISIONS.md#-d1-api-스타일)).
**금액은 전부 만원 단위**다([T4.3 파싱 규칙](./t4.3-deals-sync.md#xml-파싱-규칙--정의는-두-순수-모듈에-있다)).

### `GET /api/deals`

```
?lawdCd=11200&type=JEONSE&q=자이&apt=신금호파크자이&cursor=MTEyMDB8SkVPTlNFfDE3…&limit=20
```

`lawdCd` 생략 시 `11200`, `type` 생략 시 `SALE`, `limit` 생략 시 20(1~50).

```jsonc
// 200 — 비로그인도 받는다
{
  "region": { "code": "11200", "name": "성동구", "label": "서울 성동구" },
  "dealType": "JEONSE",
  "deals": [
    { "id": "cmf0…", "lawdCd": "11200", "dealType": "JEONSE",
      "aptName": "신금호파크자이",
      "areaM2": 59.98, "floor": 11, "dealDate": "2026-07-14",
      "price": null, "deposit": 85000, "monthlyRent": 0,   // ← 만원 단위
      "builtYear": 2016 }
  ],
  "nextCursor": "MTEyMDB8SkVPTlNFfDE3…",       // null 이면 끝
  "apartments": [ { "name": "신금호파크자이", "count": 12 } ],   // 거래 수 내림차순, 최대 100
  "trend": {
    "apartmentName": "신금호파크자이",          // null 이면 지역 전체
    "points": [ { "ym": "2026-07", "label": "7월", "count": 3,
                  "avgAmount": 85000, "minAmount": 80000, "maxAmount": 92000,
                  "avgMonthlyRent": null } ]
  },
  "sync": { "triggered": false, "reason": "CACHE_HIT", "created": 0, "months": [] }
}
```

| 실패 | status · code |
|---|---|
| 모르는 지역·유형, limit 범위 밖, 단지명 60자 초과 | 400 `VALIDATION_ERROR` |
| **다른 지역·탭의 커서 · 깨진 커서** | 400 `VALIDATION_ERROR` |

국토부가 죽어 있어도 **200 + 빈 목록 + `sync.reason: "FAILED"`** 다(화면이 문구로 알린다).

### `GET·POST·DELETE /api/transaction-alerts`

```jsonc
// GET 200 — 계정의 모든 프로필 구독, 최근 것이 위
{ "alerts": [ { "id": "cmf0…", "lawdCd": "11200", "regionLabel": "서울 성동구",
                "aptName": "신금호파크자이", "dealType": "JEONSE",
                "createdAt": "2026-09-02T05:00:00.000Z",
                "summary": "서울 성동구 · 신금호파크자이 · 전세" } ] }

// POST 요청 — 지역만 필수. 비운 칸은 «전부»
{ "lawdCd": "11200", "aptName": "신금호파크자이", "dealType": "JEONSE" }

// 201 새로 만듦 · 200 이미 있음
{ "alert": { … }, "duplicated": false }

// DELETE /api/transaction-alerts?id=cmf0… → 200
{ "deleted": true, "alertId": "cmf0…" }
```

| 실패 | status · code |
|---|---|
| 비로그인 | 401 `UNAUTHORIZED` |
| 프로필 없음(온보딩 전) | 403 `FORBIDDEN` |
| 모르는 지역·유형, 단지명 형식, `id` 없음 | 400 `VALIDATION_ERROR` |
| 없는 구독 | 404 `NOT_FOUND` |
| **남의 구독 삭제** | 403 `FORBIDDEN` |
| 계정당 20개 초과 | 409 `CONFLICT` |

- E2E① **비로그인**으로 `/deals` → 매매 4건(최신순·금액 포맷) → 전세·월세 탭 → 단지 검색 → 카드의 단지명 클릭 →
  **그 단지 추이 3점** → 새로고침해도 유지 → 알림 시트는 **로그인 유도**만
- E2E② 세입자 로그인 → 단지+유형 구독(DB 확인) → **같은 조건 재구독은 「이미 같은 조건」**(행 1개 그대로) →
  지역 전체 구독 추가 → 해제

> **국토부 API 를 E2E 에서 실호출하지 않는다.** `/deals` 는 "그 지역에 수집분이 한 줄도 없을 때만" 국토부를
> 부르므로 **테스트 DB 에 수집분을 미리 넣으면 외부 호출 경로가 아예 열리지 않는다.** Playwright 의 route mock 은
> 쓸 수 없다 — 수집은 서버(Route Handler)에서 일어나 브라우저 요청 가로채기에 걸리지 않는다. 그래서 DB 적재를
> 택했고, 같은 이유로 **이 스펙은 지역 셀렉트를 바꾸지 않는다**(수집분이 없는 지역으로 옮기면 서버가 수집을 시도한다).
> 지역 전환·온디맨드는 `app/api/deals/route.test.ts` 가 fixture mock 으로 덮는다.

export TEST_DATABASE_URL="postgresql://zari:zari@localhost:5432/zari_deals_test"
export E2E_PORT=3165
pnpm test:db && pnpm test && pnpm test:e2e
