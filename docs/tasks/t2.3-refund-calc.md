## 계산 함수 시그니처 — **T2.4 가 그대로 쓴다**

```ts
// apps/web/src/features/refund/calc.ts
import { calculateRefund } from "@/features/refund/calc";
import { kstToday } from "@/lib/rent";

const result = calculateRefund(
  { grossSalary: 48_000_000, monthlyRent: 500_000, startDate: "2024-07-01", endDate: "2025-06-30" },
  kstToday(),          // ← "오늘"은 **인자로 주입**한다. 함수 안에서 시계를 읽지 않는다
);
```

```ts
export type RefundCalcInput = {
  grossSalary: number;   // 연 총급여(원)
  monthlyRent: number;   // 월세(원/월)
  startDate: string;     // 임차 시작 `YYYY-MM-DD`
  endDate: string;       // 임차 종료 `YYYY-MM-DD`
};

export type RefundYearRow = {
  year: number;               // 귀속연도
  months: number;             // 그 해 지급 개월 수
  paidRent: number;           // months × monthlyRent
  eligibleRent: number;       // min(paidRent, annualRentCap)
  cappedOutRent: number;      // 한도 초과로 잘린 금액
  annualRentCap: number;      // 그 해 적용 한도
  creditRatePercent: number;  // 그 해 적용 공제율(%). 0 이면 대상 외
  creditAmount: number;       // floor(eligibleRent × creditRatePercent / 100)
};

export type RefundCalcResult = {
  asOf: string;                                  // 소급 기준일 `YYYY-MM-DD`
  input: RefundCalcInput;                        // 입력 그대로(응답만으로 재현 가능)
  retroRange: { fromYear: number; toYear: number };
  countedPeriod: { startDate: string; endDate: string } | null;  // 실제로 센 기간
  creditRatePercent: number;                     // 대표 공제율(기준일 연도 규칙)
  years: RefundYearRow[];                        // 지급한 달이 있는 연도만, 오름차순
  totals: { months; paidRent; eligibleRent; cappedOutRent; creditAmount };
  ineligibleReason: "GROSS_SALARY_OVER" | "NO_ELIGIBLE_MONTHS" | null;
};

export function calculateRefund(input: RefundCalcInput, asOf: Date): RefundCalcResult;

// 곁가지(전부 순수 함수)
export function rentMonthsByYear(start: Date, end: Date): Map<number, number>;
export function addMonthsClamped(base: Date, months: number): Date;   // 말일 보정
export function isFutureStart(startDate: string, asOf: Date): boolean; // API 가 400 판정에 쓴다
export function defaultRefundPeriod(asOf: Date): { startDate: string; endDate: string };
```

`asOf` 는 **선택 인자가 아니라 필수 두 번째 인자**다. 기본값을 두면 호출부가 조용히 시계에
의존하게 되고, 같은 입력이 날마다 다른 답을 낸다(크론 T1.4 가 `now` 를 받는 것과 같은 이유).

### T2.4 가 이어 붙일 자리

- **스키마 변경이 필요 없다.** `RefundApplication` 이 이미 있고 결과가 그대로 매핑된다:
  `annualIncome ← input.grossSalary` · `startYear ← years[0].year` · `endYear ← years.at(-1).year` ·
  `expectedAmount ← totals.creditAmount`.
- CTA 가 계산 입력을 쿼리로 넘긴다 — `/tenant/refund/apply?grossSalary=…&monthlyRent=…&startDate=…&endDate=…`.
  그 값을 `calculateRefund` 에 그대로 넣으면 **계산기가 보여 준 금액이 그대로 재현된다.**
- 신청 시점에 금액을 다시 굳힐 때도 `kstToday()` 를 주입해 이 함수를 부른다. 계산식을 두 벌로
  만들면 화면 금액과 신청 금액이 갈라진다.

## 연도별 상수 테이블 구조

```ts
// apps/web/src/features/refund/rules.ts
export type RefundTaxRule = {
  effectiveFrom: number;        // 이 규칙이 적용되기 시작하는 **귀속연도**
  annualRentCap: number;        // 공제 대상 월세 연 한도(원)
  brackets: readonly { upToGrossSalary: number; creditRatePercent: number }[]; // 상한 오름차순
};

export const REFUND_TAX_RULES: readonly RefundTaxRule[] = [
  {
    effectiveFrom: 2020,
    annualRentCap: 10_000_000,
    brackets: [
      { upToGrossSalary: 55_000_000, creditRatePercent: 17 },
      { upToGrossSalary: 80_000_000, creditRatePercent: 15 },
    ],
  },
];

export const REFUND_RETRO_YEARS = 5;     // 기준일 연도를 **포함**해 5개
export const NOT_ELIGIBLE_RATE = 0;

export function resolveRefundRule(year: number): RefundTaxRule;                       // 귀속연도 → 규칙
export function resolveCreditRatePercent(grossSalary: number, rule: RefundTaxRule): number;
export function retroYearRange(asOf: Date): { fromYear: number; toYear: number };
```

- **구간 경계는 "이하"** — 5,500만원 정확히는 17%, 여기 1원만 더하면 15%, 8,000만원 정확히는 15%,
  1원만 더하면 대상 외(0%).
- `resolveRefundRule(year)` 는 `effectiveFrom ≤ year` 인 것 중 **가장 최근** 규칙을 쓰고,
  테이블보다 오래된 연도는 **가장 오래된 규칙**을 그대로 적용한다(계산식에 null 분기를 들이지 않으려고).
- **지금은 현행 규칙 한 벌만 담았다.** task 가 정한 5,500/8,000·1,000만원 그대로다.
  개정분이 나오면 엔트리 한 줄만 얹으면 되고 `calc.ts` 는 바뀌지 않는다 —
  예: `{ effectiveFrom: 2027, annualRentCap: 12_000_000, brackets: [...] }`.
  단위 테스트가 "테이블이 `effectiveFrom` 오름차순이고 구간도 상한 오름차순"이라는 전제를 지킨다.

## 결정 — 부분 연도 · 소급 기준 · 반올림

| 항목 | 결정 | 근거 |
|---|---|---|
| **소급 기준일** | 호출자가 넘긴 `asOf`. 운영은 `kstToday()`(`@/lib/rent`), 테스트는 고정 날짜 | 계산이 시계에 의존하면 같은 입력이 날마다 다른 답을 낸다. "신청 시점"이 아니라 "요청을 처리하는 그 순간"으로 못박아, 계산기와 T2.4 신청이 같은 기준을 본다 |
| **소급 범위** | `asOf` 연도를 **포함**해 최근 5개 연도 (`[asOfYear-4, asOfYear]`) | "5년"을 **연도 개수 5개**로 읽는다. 화면 문구("최근 5년")와 개수가 맞고, 올해분을 포함해야 지금 사는 집의 월세가 잡혀 체감 금액이 맞는다. 기준일이 2026년이면 2022~2026년분이 대상이고 2021년분은 기한이 지난 것으로 본다 |
| **지급 개월** | 임차 **시작일 기준 월 주기** — k번째 주기(`시작일 + k개월`, 말일 보정)의 시작일이 계산 종료일 이내면 1개월 | 월세는 달 단위로 낸다. **달력 월로 세면 3/15~다음해 3/14 짜리 12개월 계약이 13개월로 부풀고**, 일할로 쪼개면 실제 지급액과 어긋난다(3월 15일 입주여도 3월분은 한 달치를 낸다) |
| **부분 연도** | 각 주기의 **시작일이 속한 연도**에 1개월씩 귀속 | 7월 15일 입주면 그 해는 6개월치, 나머지는 다음 해로 자연히 갈린다. 연도 합계가 자동으로 12개월을 넘지 않는다 |
| **말일 보정** | 없는 날이면 그 달 말일로 당기고, 보정은 **언제나 원래 일자**에서 다시 한다 | 1/31 → 2/28 → **3/31**. 원장 엔진의 `dueDateFor` 와 같은 규칙이라 날짜가 밀려 쌓이지 않는다 |
| **미래분** | 계산 종료일 = `min(임차 종료일, asOf)` | 소급 환급은 **이미 지급한** 월세에 대한 것이다. 계약이 내년까지여도 오늘까지만 센다 |
| **반올림** | **내림(`Math.floor`)** — `floor(eligibleRent × rate / 100)` | 원장 엔진(T1.4) 연체료가 `floor` 다. 1원 미만을 올리면 화면이 실제보다 많은 금액을 약속하게 된다. 곱셈은 정수끼리라(최대 1,000만 × 17) 부동소수 오차가 없다 |
| **총급여** | 소급 전 연도에 **같은 값**을 적용 | 계산기 입력이 하나다. 연도별 급여를 따로 받는 건 T2.4 신청서에서 다룰 문제고, 규칙 해석은 이미 연도별로 갈려 있어 확장 지점이 열려 있다 |

### 실패를 400 으로 볼 것인가, 0원으로 볼 것인가

| 입력 | 처리 | 왜 |
|---|---|---|
| 금액 0원·음수·소수·문자 | **400** `VALIDATION_ERROR` | 오타다. 0원을 계산해 주면 사용자가 실수를 못 알아챈다 |
| 기간 역전(시작 > 종료) | **400** | 같은 이유 |
| 달력에 없는 날짜(`2026-02-31`) | **400** | 형식만 맞는 값 — T1.2 와 같은 처리 |
| **임차 시작일이 미래** | **400** | 아직 낸 월세가 한 푼도 없다. 0원을 돌려주면 날짜 오타와 구분되지 않는다 |
| **소급 5년보다 오래된 기간** | **200**, `years: []` · `ineligibleReason: "NO_ELIGIBLE_MONTHS"` | 입력은 유효하다. "기한이 지났다"가 계산기의 **답**이지 오류가 아니다 |
| **총급여 8,000만원 초과** | **200**, 공제율 0 · `ineligibleReason: "GROSS_SALARY_OVER"` | 같은 이유. 지급 월세는 그대로 보여 줘서 화면이 사유를 설명할 수 있게 한다 |

## 공개 라우트 위치 — `(app)/refund/calculator`

```
app/
├─ (app)/                      ← 480px 셸(D5) + (프로필이 있으면) 하단 탭바
│  ├─ page.tsx                 `/` 랜딩(비로그인 허용)
│  ├─ search/                  `/search` (T3.2, 비로그인 허용)
│  ├─ notice/[token]/          `/notice/<token>` (T1.8, 비로그인 허용)
│  ├─ refund/calculator/       `/refund/calculator` ← **여기** (T2.3, 비로그인 허용)
│  └─ (protected)/             ← layout 이 requireUser() → 비로그인이면 /login
└─ (auth)/                     로그인·온보딩 전용(탭바 없음)
```

- 로그인 강제는 `(app)/(protected)/layout.tsx` **한 곳**이 한다(T0.5). 그 그룹 **밖**,
  `(app)` 바로 아래에 두면 **480px 셸은 그대로 쓰면서 로그인은 걸리지 않는다** —
  T1.8 공개 고지서가 앉은 자리와 같고, T0.5 가 `/refund/calculator` 를 그렇게 두기로 이미 정해 뒀다.
- 비로그인 방문자에게는 탭바가 그려지지 않는다(`AppShell` 은 프로필이 없으면 탭바를 뺀다).
- E2E 가 "비로그인으로 열리는가"를 직접 지킨다(`/api/me` 401 + `/login` 리다이렉트 없음).
- 서버 컴포넌트가 하는 일은 셋뿐이다: **기준일(`kstToday()`)**, **로그인 여부**(CTA 목적지만 바뀐다),
  **폼 기본 기간**(클라이언트가 `new Date()` 로 만들면 하이드레이션이 갈린다).

### SEO·OG — 고지서(T1.8)와 정반대로 **색인을 연다**

정적 `metadata` 객체를 쓴다. 값이 요청 정보(params·쿠키)에 전혀 의존하지 않아서인데,
Next 문서가 그 경우 정적 객체를 쓰라고 못박는다(`03-api-reference/04-functions/generate-metadata.md`).
T1.8 이 `generateMetadata` 함수를 쓴 이유는 토큰마다 제목이 달라지기 때문이고, 여기는 아니다.

| 항목 | 값 |
|---|---|
| `title` | `월세 환급 계산기 — 최근 5년 세액공제 소급 조회 · 자리 데모` |
| `description` | 공제율·소급 범위 + "데모용 추정치이며 실제 세법 자문이 아닙니다" |
| `keywords` | 월세 세액공제 · 월세 환급 · 연말정산 · 경정청구 · 월세 공제 계산기 |
| `alternates.canonical` | `/refund/calculator` |
| **`robots`** | **`{ index: true, follow: true }`** — 개인정보가 한 줄도 없는 **유입 경로**다(고지서는 `noindex`) |
| `openGraph` | `type: website` · `siteName` · `locale: ko_KR` · `url` · 같은 title·description |
| `twitter` | `card: summary` |
| `metadataBase` | `NEXT_PUBLIC_WEB_URL`(없으면 localhost) |

|---|---|
| 로그인 | `/tenant/refund/apply?grossSalary=…&monthlyRent=…&startDate=…&endDate=…` (T2.4 — **아직 없어 404 가 정상**) |
| 비로그인 | `/login?from=refund_calculator&next=<위 신청 경로>` |

T1.8 이 공개 고지서 CTA 에서 푼 방식을 그대로 따랐다.

1. **anonId 로 잇는다(본선)** — `zari_anon` 1st-party 쿠키(T0.7)가 계산기 → 로그인 → 온보딩까지
   같은 값으로 유지되므로 퍼널이 한 방문자로 묶인다. E2E 가 이 anonId 로 순서를 검증한다.
2. **쿼리로 출처를 남긴다(보조)** — `page_view` 가 쿼리까지 포함한 경로를 기록하므로
   로그인·가입 이벤트의 `path` 에 "환급 계산기에서 왔다"가 남는다. 로그인 화면(T0.4 소유)은
   아직 이 값을 읽지 않는다 — **그 파일을 건드리지 않고** 출처를 잇기 위한 선택이다.
3. 클릭 시 `flush()` 로 큐를 즉시 비운다 — 화면 전환 중 이벤트가 유실되지 않게.
