# T0.3 인증 API

> Phase 0 · 상태: ✅ · [Phase 구성](../PHASES.md)

- **내용**: 모의 OTP — 실제 SMS 없이 코드가 응답·발송로그에 노출. 세션은 httpOnly 쿠키

| 엔드포인트 | 동작 |
|---|---|
| `POST /api/auth/otp/request` | OtpCode 생성(5분 만료), 응답에 코드 포함(데모 노출) + MessageLog(OTP) 기록 |
| `POST /api/auth/otp/verify` | 검증 → 기존 User면 Session 발급, 신규면 가입 티켓 반환 |
| `POST /api/auth/demo-login` | 시드 계정 4종 중 하나로 즉시 세션 발급 |
| `POST /api/auth/logout` | 세션 삭제 |
| `GET /api/me` | 내 User + 프로필 목록 + 활성 프로필 |

## 요청·응답 (실제 구현 형태)

에러는 전부 `{ "error": { "code", "message", "details?" } }` 한 형태([D1](../DECISIONS.md#-d1-api-스타일)).
전화번호는 하이픈이 있어도 받고 **정규화(숫자만)해서 저장·조회·응답**한다.

### `POST /api/auth/otp/request`

```jsonc
// 요청
{ "phone": "010-1111-1111" }
// 200 — code 는 데모 노출용(실서비스라면 절대 금지). MessageLog(kind=OTP) 에도 같은 코드가 남는다
{ "phone": "01011111111", "code": "482913", "expiresAt": "2026-09-01T09:05:00.000Z" }
```

| 실패 | status · code |
|---|---|
| 휴대폰 형식 아님 | 400 `VALIDATION_ERROR` |

### `POST /api/auth/otp/verify`

```jsonc
// 요청
{ "phone": "01011111111", "code": "482913" }

// 200 — ① 기존 회원: httpOnly 세션 쿠키(zari_session) + 활성 프로필 쿠키(zari_profile) 설정.
//      status 를 뺀 나머지는 GET /api/me 와 같은 모양이다
{ "status": "SESSION", "user": { … }, "profiles": [ … ], "activeProfile": { … } }

// 200 — ② 신규 번호: 세션 없음. 온보딩(T0.4)으로 보낼 가입 티켓을 준다
{
  "status": "SIGNUP_REQUIRED",
  "phone": "01011111111",
  "signupTicket": "cmf0…",                        // 검증 완료된 OtpCode 레코드 id
  "ticketExpiresAt": "2026-09-01T09:10:00.000Z"   // 10분
}
```

| 실패 | status · code |
|---|---|
| 발급된 적 없는 코드(오입력·다른 번호 코드) | 400 `OTP_INVALID` |
| 5분 지난 코드 | 400 `OTP_EXPIRED` |
| 이미 검증에 쓴 코드(재사용) | 409 `OTP_ALREADY_USED` |
| 번호·코드 형식 오류(코드는 6자리 숫자) | 400 `VALIDATION_ERROR` |

### `POST /api/auth/demo-login`

```jsonc
// 요청 — 역할 키 4종
{ "role": "landlord" }   // landlord | tenant | realtor | master
// 200 — GET /api/me 와 같은 모양. 세션 쿠키 + 역할과 같은 유형의 활성 프로필 쿠키가 설정된다
{ "user": { … }, "profiles": [ … ], "activeProfile": { … } }
```

역할 → 시드 계정 매핑은 `apps/web/src/lib/auth/demo-accounts.ts` 의 `DEMO_ACCOUNTS`
(라벨·설명 포함 — 로그인 화면 버튼에 그대로 쓰면 된다). 시드가 없으면 404.

| 실패 | status · code |
|---|---|
| 시드 계정 없음(`pnpm db:seed` 안 함) | 404 `NOT_FOUND` |
| 모르는 역할 키 | 400 `VALIDATION_ERROR` |

### `POST /api/auth/logout`

본문 없음 → `204 No Content`. Session 레코드 삭제 + 세션·활성프로필 쿠키 제거. 비로그인이어도 204(멱등).

### `GET /api/me`

```jsonc
// 200
{
  "user": { "id": "cmf0…", "name": "이중개", "phone": "01033333333", "isAdmin": false },
  "profiles": [
    {
      "id": "cmf0…",
      "type": "REALTOR",                    // LANDLORD | TENANT | REALTOR | MASTER
      "createdAt": "2026-09-01T00:00:00.000Z",
      "realtorDetail": { "profileId": "cmf0…", "officeName": "왕십리부동산", "lat": 37.56133, … },
      "masterDetail": null
    }
  ],
  "activeProfile": { … }                    // 프로필이 없으면(온보딩 전) null
}
```

`realtorDetail`·`masterDetail` 은 해당 유형 프로필에만 채워지고 나머지는 null.
비로그인·만료 세션·DB에 없는 토큰은 전부 401 `UNAUTHORIZED`.

## 뒤 task 가 쓸 것

- **가입 티켓** — 스키마를 늘리지 않으려고 **검증 완료된 `OtpCode` 레코드 id** 를 티켓으로 쓴다.
  검증 시 `verifiedAt` 을 찍어(코드 재사용 차단) `expiresAt` 의 의미를 *코드 만료(5분)* 에서
  *티켓 만료(10분)* 로 바꾼다. 기존 회원이면 티켓으로 못 쓰게 `expiresAt` 을 즉시 만료시킨다.
  티켓은 1회용 — 소진 시 레코드를 삭제한다. 자세한 표는 `apps/web/src/lib/auth/otp.ts` 상단 주석.

  ```ts
  // apps/web/src/lib/auth/otp.ts — T0.4 POST /api/profiles 에서 사용
  type SignupTicketResult =
    | { ok: true; phone: string; expiresAt: Date }
    | { ok: false; reason: "NOT_FOUND" | "NOT_VERIFIED" | "EXPIRED" };

  verifySignupTicket(ticket: string): Promise<SignupTicketResult>   // 검증만(번호 미리 채우기)
  consumeSignupTicket(ticket: string): Promise<SignupTicketResult>  // 검증 + 소진(가입 확정 시)
  ```

  실패 시 응답 코드는 `SIGNUP_TICKET_INVALID`(400) 를 쓴다(`lib/api/response.ts` 에 정의됨).
- **로그인 처리** — `loginUser(user, preferredType?)` (`lib/auth/session.ts`): 세션 발급 +
  활성 프로필 쿠키 초기화까지 한 번에. `preferredType` 이 있으면 그 유형 프로필을 활성으로 잡는다.
- **응답 조립** — `buildMeResponse(user)` (`lib/auth/me.ts`): `GET /api/me` 와 같은 모양을 만든다.
  로그인 응답도 이걸 쓰므로 클라이언트가 `/api/me` 쿼리 캐시를 바로 채울 수 있다.
- **전화번호** — `normalizePhone` · `phoneSchema` · `formatPhone` (`lib/phone.ts`).
