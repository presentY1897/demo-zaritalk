> Phase 1 · 상태: ✅ · [Phase 구성](../PHASES.md)

**임대인 탭바의 "홈"**(경로는 [T0.5](./t0.5-shell-profile.md) 배정표 그대로)이고 데모에서 가장 먼저 보이는 화면이다.

**숫자는 한 줄도 직접 계산하지 않는다.** 전부 원장 엔진([T1.4](./t1.4-rent-engine.md) `@/lib/rent`)에 위임한다.

|---|---|
| 청구 상태·잔액·항목 분해 | `describeCharge(charge, asOf)` (내부적으로 `resolveChargeStatus`·`calcOutstanding`) |
| 부분납 포함 미납 판정 | `isDelinquent(charge, asOf)` |

| "오늘"·"이번 달" | `kstToday(now)` · `kstYearMonth(asOf)` |
| 호실 상태(자산 카드) | [T1.1](./t1.1-building-unit.md) `deriveUnitStatus` |

## "연체"가 두 가지다 — 화면에서 라벨로 구분한다

| 화면 문구 | 뜻 | 판정 | 시드 기준 |
|---|---|---|---|
| **연체 1건 / 1,015,500원** (danger 배지 + 큰 숫자) | 기한이 지났는데 **한 푼도 안 낸** 청구 | 실효 상태 `OVERDUE` | **1건 · 1,015,500원** |
| **부분납 포함 미납** (같은 카드 하단 각주) | 기한이 지나고 **잔액이 남은** 청구 전부 | `isDelinquent()` | **2건 · 1,315,500원** |

- 큰 숫자 아래에 "기한이 지났는데 한 푼도 안 낸 청구입니다." 라고 적어 좁은 정의를 못 박고,
  넓은 정의는 구분선 아래 각주(`data-testid="home-delinquent"`)에 **다른 라벨**로 둔다. 두 숫자가 나란히 보인다.
- 연체는 미납의 부분집합이다(7월 부분납 잔액 300,000원이 미납에만 더해져 1,315,500원이 된다).

### 저장된 `status` 컬럼이 아니라 "실효 상태"를 쓴다

`RentCharge.status` 는 크론이 하루 1회 갱신하는 스냅샷이라, 크론이 돌기 전에는 기한이 지난 청구가
아직 `SCHEDULED` 로 남아 있을 수 있다. 대시보드는 `asOf`(KST 오늘)로 `describeCharge()` 를 다시 태운
상태를 쓴다 — **규칙이 같은 함수**라 크론이 돈 뒤에는 두 값이 언제나 일치하고, 안 돌았을 때만 화면이 더 정확하다.
(시드 기준으로는 두 값이 완전히 같다.)

## 시드 기준 실제 숫자 (오늘 = 2026-09-01 KST)

| 카드 | 값 |
|---|---|
| 기준일 | `2026-09-01` |
| 이번 달 | 2026년 9월 — 청구 **1건 700,000원**, 수납 **0원**, 미수금 700,000원, 수납률 **0%**, 상태 `예정 1` |
| 연체 | **1건 · 1,015,500원** — 행당해피빌 201호 · 박세입 · 2026년 8월분 · 기한 2026.08.05 · **27일 경과** |
| 연체 항목 분해 | 월세 650,000 + 관리비 50,000 + 전월 이월 300,000 + 연체료 15,500 |
| 부분납 포함 미납 | **2건 · 1,315,500원** (7월 부분납 잔액 300,000 + 8월 1,015,500) |
| 만기 90일 이내 | **0건** — 시드 계약 만기가 2027-02-28 · 2027-07-24 라 90일 밖이다(빈 상태 문구가 뜬다) |
| 자산 | 건물 **1** · 호실 **3** — 대기 1 · 연체 1 · 공실 1 |
| 미확인 민원·견적 | **0** — 카드를 통째로 숨긴다 |

> 연체료 15,500원은 시드가 원장 엔진 규칙 `floor(이월 300,000 × 5% × 31일(7/5→8/5) / 30)` 으로
> 맞춰 둔 값이다(`ef28c29` — 그 전에는 손으로 넣은 30일치 15,000원이었다).
> 그래서 연체 총액은 **1,015,500원**이고, `lib/rent/ledger.test.ts` 의 "시드 시나리오" 가 같은 값을 못 박고 있다.

## 미확인 민원·견적 배지

`Complaint`·`WorkOrderQuote` 는 **이미 스키마에 있으므로 집계를 진짜로 구현**했다.

- 미확인 민원 = 내 건물의 계약에 달린 `Complaint.status === OPEN`
- 미확인 견적 = 내가 낸 작업 의뢰에 달린 `WorkOrderQuote.status === PROPOSED`
- 시드에 데이터가 없어 지금은 **0 이고 카드가 통째로 숨는다**(정상).
  **[T2.6](./t2.6-complaint.md)·[T5.3](./t5.3-quote.md) 데이터가 들어오면 코드 변경 없이 자동으로 채워진다** —
  민원 1건·견적 1건을 DB에 넣어 배지가 뜨는 것까지 확인했다.
