# T6.4 SEO 마무리

> Phase 6 · 상태: ✅ · [Phase 구성](../PHASES.md)

Phase 1~4 에서 각 화면이 **자기 메타만** 챙겼다. 그 결과 ①사이트 URL 을 화면마다 다르게
구했고 ②`sitemap.xml`·`robots.txt` 가 아예 없었으며 ③랜딩·실거래가에는 canonical·OG 가
없었다. 이 task 가 그 셋을 한 곳으로 모은다.

## 사이트 URL — `lib/seo.ts` 한 곳

```ts
siteUrl(): string          // SITE_URL → NEXT_PUBLIC_SITE_URL → NEXT_PUBLIC_WEB_URL
                           // → VERCEL_PROJECT_PRODUCTION_URL → VERCEL_URL → localhost
siteUrlObject(): URL       // 루트 layout 의 metadataBase
absoluteUrl(path): string  // canonical·OG·sitemap 이 같은 함수를 쓴다
SITE_NAME · SITE_DESCRIPTION · INDEXABLE · NOT_INDEXABLE
```

**`SITE_URL`(서버 전용)을 가장 먼저 보는 이유** — `NEXT_PUBLIC_*` 는 번들러가 **빌드 시점에
인라인**한다. robots·sitemap 처럼 서버에서만 도는 라우트가 빌드 환경의 도메인으로 굳어,
로컬에서 빌드하면 `Sitemap: http://localhost:3000/...` 이 박혀 나갔다(실제로 겪고 고쳤다).
클라이언트 번들에는 `SITE_URL` 이 들어가지 않으므로 그쪽은 `NEXT_PUBLIC_*` 로 떨어진다.

`metadataBase` 는 **루트 layout 에 한 번만** 둔다 — 하위 화면의 상대 canonical·OG 가 전부
이걸 기준 삼는다. 화면마다 각자 구하면 프리뷰 배포에서 도메인이 어긋난다.

## robots 정책 — 화면마다 이유가 다르다

| 화면 | 정책 | 이유 |
|---|---|---|
| `/` | index | 비로그인 방문자가 보는 유일한 소개 화면 |
| `/search` | index + canonical `/search` | 필터 URL 을 한 곳으로 모은다 |
| `/listings/[id]` OPEN | index | 개인정보 0(등록자 이름도 DTO 에 없다), 검색 유입이 목적 |
| `/listings/[id]` RESERVED·CLOSED | noindex, follow | 이미 나간 매물이 검색에 남으면 안 된다 |
| `/refund/calculator` | index | 개인정보 0인 유입 경로 |
| `/deals` | index + canonical `/deals` | 공개 데이터 |
| `/notice/[token]` | **noindex** | **개인 고지서** — 토큰만 알면 열린다 |
| `(auth)`·`(protected)` | 색인 대상 아님 | 로그인 화면·개인 데이터 |

`robots.txt` 는 경로 단위로 한 번 더 막는다(`/api/`·`/notice/`·로그인·역할별 화면·`/community/`).
화면 메타와 이중으로 두는 이유: 메타는 렌더된 페이지에만 붙고, 크롤러가 링크를 따라오기 전에
막는 것은 `robots.txt` 다.

## sitemap

고정 화면 4개(`/`·`/search`·`/deals`·`/refund/calculator`) + **OPEN 매물 상세**(최대 1000, 최신순).
- 예약·종료 매물은 **넣지 않는다** — 상세가 스스로 `noindex` 라 넣으면 서로 어긋난다.
- `/notice/[token]` 은 개인 고지서라 애초에 제외.
- DB 를 읽으므로 `force-dynamic`. **DB 가 막혀도 고정 화면만이라도 나가도록** try/catch 로 감쌌다.

`robots.ts` 도 `force-dynamic` 이다(위의 빌드 시점 인라인 문제).
