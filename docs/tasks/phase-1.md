# Phase 1 — 임대인 코어 (자산·계약·수납·고지)

> 스펙: [§2 건물·호실·계약](../specs/02-lease.md) · [§3 수납 원장](../specs/03-rent-ledger.md) · [§4 고지서](../specs/04-notice.md) · [§14 크론](../specs/14-cron.md)

## ⬜ T1.1 건물·호실 관리

- **내용**: buildings·units CRUD API + `/landlord/buildings`(목록·등록), `/landlord/buildings/[id]`(호실 그리드), `/landlord/units/[id]`(상세). 주소 입력은 카카오 키 전까지 수동(주소 문자열+지도 클릭 좌표), 키 수령 후 주소 검색으로 교체
- **완료 기준**: 건물→호실 등록·수정·삭제가 화면에서 완주, 호실 그리드에 계약중/공실 상태 색 표시
- **최소 테스트**: units — `@@unique([buildingId,label])` 중복 409, 타인 건물 접근 403
- **통합 테스트**: (T1.2와 묶음)

## ⬜ T1.2 계약 등록·관리

- **내용**: leases CRUD API + `/landlord/leases/new`, `/landlord/leases/[id]`. 등록 시 당월 RentCharge 즉시 생성, 종료(ENDED) 처리
- **완료 기준**: 계약 등록 → PENDING_TENANT 상태 + 당월 청구 자동 생성 확인, 계약 상세에서 조건·연결 상태 표시
- **최소 테스트**: 등록 시 청구 생성(당월 1건, dueDate=납부일), 잘못된 기간(start>end) 400, 동일 호실 기간 중복 계약 409
- **통합 테스트**: **E2E** 임대인 로그인 → 건물·호실·계약 등록 → 호실 그리드에 계약중 표시

## ⬜ T1.3 세입자 연결

- **내용**: `GET /api/tenant/pending-leases`, `POST /api/leases/[id]/accept·decline` + `/tenant/leases/accept` 화면, 세입자 홈 `/tenant` 계약 카드
- **완료 기준**: 시드의 홍미가 번호(01055555555)로 신규 가입 → 대기 계약 노출 → 수락 → ACTIVE + 세입자 홈에 계약 표시
- **최소 테스트**: accept — 전화번호 불일치 프로필 403, 이미 ACTIVE인 계약 409, 수락 시 tenantProfileId·tenantAcceptedAt 기록
- **통합 테스트**: **E2E** 신규 세입자 가입 → 계약 수락 → 세입자 홈에서 9월 납부 예정 확인

## ⬜ T1.4 원장 엔진 (청구 생성·이월·연체)

- **내용**: 원장 규칙을 순수 함수 모듈로(`packages/db` 또는 web lib) — 당월 청구 생성(멱등), OVERDUE 전환, 미납 이월(carriedOver), 연체료 일할 계산. 크론 엔드포인트 `POST /api/cron/daily` + 어드민 수동 트리거
- **완료 기준**: 크론 2회 연속 실행해도 중복 청구 없음(멱등), 시드 데이터 기준 상태 전이가 규칙대로
- **최소 테스트**: **이 Phase의 핵심 단위 테스트.** ①멱등 생성 ②부분납 상태 전이(0<paid<total→PARTIALLY_PAID, 도달→PAID) ③이월 금액 계산 ④연체료 일할(rate null이면 0) ⑤말일 보정(paymentDay 31 → 2월)
- **통합 테스트**: 크론 실행 → 신규 월 청구 + OVERDUE 전환을 DB로 검증하는 API 테스트

## ⬜ T1.5 수납 UI (청구·납부)

- **내용**: `/landlord/leases/[id]` 수납 탭(청구 리스트·상태 배지), 청구 상세 시트(납부 타임라인, 받음 체크, 가상 입금), `POST /api/charges/[id]/payments`, `DELETE /api/payments/[id]`
- **완료 기준**: 시드의 6~9월 4개 상태(완납/부분납/연체/예정)가 화면에 구분 표시, 가상 입금 → 즉시 상태 반영
- **최소 테스트**: payments API — 초과 납부 400, 부분납 누적 후 완납 전이, 삭제 시 상태 재계산
- **통합 테스트**: **E2E** 8월 연체 청구에 가상 입금(전액) → 완납 배지 + 대시보드 연체 수 감소

## ⬜ T1.6 임대장부

- **내용**: `GET /api/landlord/ledger?year=` 집계 + `/landlord/ledger` 화면(월별 합계, 건물 필터, 월세·관리비·연체료 구분, 미니 차트)
- **완료 기준**: 시드 납부 기록이 월별로 정확히 집계되어 표시
- **최소 테스트**: 집계 쿼리 — 월 경계(paidAt 기준), 항목 구분 합계 검증
- **통합 테스트**: 없음 (API 테스트로 충분)

## ⬜ T1.7 고지서 발송

- **내용**: `POST /api/leases/[id]/notices`(템플릿 렌더+token 발급), 발송 시트(카톡 말풍선 미리보기), `/landlord/messages` 발송 이력
- **완료 기준**: 3종(월세/연체/만기) 발송 가능, 이력에 열람 여부 표시
- **최소 테스트**: 발송 API — kind별 템플릿 본문 스냅샷, token 유니크
- **통합 테스트**: (T1.8과 묶음)

## ⬜ T1.8 공개 고지서 페이지

- **내용**: `/notice/[token]` — 청구 상세·납부 안내·가입 CTA, 첫 조회 openedAt 기록, `notice_view` 트래킹, OG 메타
- **완료 기준**: 시드 토큰 `demo-notice-hong`이 비로그인으로 열리고, 열람 후 임대인 발송 이력에 "열람" 표시
- **최소 테스트**: 잘못된 토큰 404, openedAt 최초 1회만 기록
- **통합 테스트**: **E2E(그로스 핵심 여정)** 임대인이 고지서 발송 → 비로그인 브라우저로 공개 페이지 열람 → CTA 클릭 → 가입 → 대기 계약 수락. `notice_view→notice_cta_click→signup_*` 이벤트가 순서대로 쌓임

## ⬜ T1.9 임대인 홈 대시보드

- **내용**: `GET /api/landlord/summary` + `/landlord` 홈(수납 현황, 연체 리스트, 만기 임박 카드)
- **완료 기준**: 시드 기준 "연체 1건 1,015,000원 / 이번 달 예정 2건" 등 숫자가 정확
- **최소 테스트**: summary 집계 — 연체 건수·금액, 만기 90일 필터
- **통합 테스트**: 없음
