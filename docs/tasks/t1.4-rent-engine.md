# T1.4 원장 엔진 (청구 생성·이월·연체)

> Phase 1 · 상태: ✅ · [Phase 구성](../PHASES.md)

**Phase 1 전체가 공유하는 돈 계산 코어다.** 청구·납부·연체 계산식은 `apps/web/src/lib/rent/` 한 곳에만 있고
T1.2(계약)·T1.5(수납 UI)·T1.6(장부)·T1.9(대시보드)는 여기서 export 한 함수를 가져다 쓴다.
**직접 계산식을 다시 쓰지 말 것** — 필요한 계산이 없으면 이 모듈에 추가한다.

- **원장 규칙** (순수 함수 모듈로 구현)
  - 매일 크론이 ACTIVE 계약의 당월 청구 생성(멱등). `totalDue = 월세 + 관리비 + 전월 이월 + 연체료`
  - 납부(수동·가상·카드)는 RentPayment 행으로 쌓고 `paidAmount` 누적 — 0<paid<total → PARTIALLY_PAID, 도달 → PAID
  - 납부일 경과 → OVERDUE. 미납 잔액은 익월 청구 `carriedOverAmount`로 이월, `lateFeeRatePct` 있으면 연체료 일할 가산
- **크론**: `POST /api/cron/daily`(시크릿 헤더 인증) — 청구 생성·연체 전환·이월·연체료 + 만기 90일 전 CONTRACT_EXPIRY 알림 1회. 어드민 수동 트리거 버튼(`/cron`) 제공

## ② 계산 규칙

| 규칙 | 내용 |
|---|---|
| **총액** | `totalDue = rentAmount + maintenanceAmount + carriedOverAmount + lateFeeAmount` |
| **상태 우선순위** | `PAID` > `PARTIALLY_PAID` > `OVERDUE` > `SCHEDULED` |
| **기한 판정** | `asOf > dueDate` 부터 연체. **기한 당일은 아직 연체가 아니다** |
| **이월** | 전월 미납 잔액 `max(0, totalDue - paidAmount)` → 익월 `carriedOverAmount`. 전월 청구가 없으면 0 |
| **연체료** | `floor(이월액 × lateFeeRatePct/100 × 연체일수 / 30)`. `lateFeeRatePct` 가 null·0 이하면 **0** |
| **연체일수(청구 생성 시)** | 전월 납부기한 → 이번 납부기한 사이 일수 (예: 7/5→8/5 = 31일) |
| **반올림** | **내림(floor)** — 1원 미만은 세입자에게 유리한 쪽으로 버린다. 부동소수 오차는 소수 6자리에서 정리 후 내림 |
| **충당 순서** | **이월 → 연체료 → 관리비 → 월세** (민법 479조 취지: 오래된 채무·이자 먼저, 관리비는 실비라 월세보다 먼저). 총액 초과분은 `excess` |
| **표시 순서** | **월세 → 관리비 → 전월 이월 → 연체료** (충당 순서와 다르다) |
| **말일 보정** | `paymentDay` 가 그 달에 없으면 말일로 당긴다. 31 → 2월이면 28(윤년 29), 30일 달이면 30. 0·음수는 1일로 |
| **음수 방지** | 모든 금액은 `max(0, trunc(x))` 로 정규화. 잔액·연체료·이월액에 음수가 생기지 않는다 |
| **0원 청구** | `totalDue = 0` 이면 곧바로 `PAID` (전세 등 받을 게 없는 달) |

### 타임존

- `@db.Date` 컬럼(`dueDate`·`startDate`·`endDate`)은 **UTC 자정**으로 다룬다 — 시드의 `d()` 와 같은 규칙.
  KST 자정으로 넣으면 UTC 로는 전날 15:00 이라 Postgres `date` 로 잘릴 때 하루가 밀린다.
- **"오늘"은 KST 달력 기준**이다. 크론은 UTC 로 도는데 UTC 자정~KST 자정 사이 9시간 동안 한국은 이미 다음 날이다.
  `kstToday(now)` 가 이 경계를 한 곳에서 처리하고, KST 달력의 오늘을 **UTC 자정 Date** 로 돌려주므로
  `dueDate` 와 그대로 비교할 수 있다. 상태 판정 함수의 `asOf` 에는 **항상 `kstToday()` 를 넘긴다.**
- 타임스탬프 컬럼(`paidAt`·`sentAt`)은 시각 그대로다. 월별로 묶을 때는 `kstYearMonth(paidAt)` 을 쓴다(T1.6).

### 크론이 **건드리지 않는 것** — 확정 청구 불변

이미 만들어진 청구의 **금액은 다시 계산하지 않는다.** 매일 연체료를 키우면 ① 화면 숫자가 매일 달라져
데모가 흔들리고 ② 이미 고지서로 나간 금액이 사후에 바뀐다. **연체료는 다음 달 청구에 얹는다.**

유일한 예외가 **이월 정정**이다 — *이월액이 이미 실려 있고(`carriedOverAmount > 0`) 아직 기한 전(`dueDate > 오늘`)*인
청구만, 전월의 늦은 납부·납부 취소를 반영해 이월액·연체료·총액을 다시 맞춘다.
이월이 0인 청구에 뒤늦게 이월을 얹지는 않는다(예고 없이 청구가 늘지 않게).

> **시드와의 차이 한 곳** — 시드의 8월 청구 연체료 15,000원은 손으로 넣은 값(30일치)이고,
> 엔진 규칙(7/5→8/5 = 31일)으로는 15,500원이 된다. 크론은 기존 청구를 건드리지 않으므로
> **시드 값 1,015,000원은 그대로 유지된다** (T1.9 의 "연체 1건 1,015,000원" 기준 그대로).
> 실제로 시드 DB에 크론을 두 번 돌려 6~9월 4개 상태·금액이 한 글자도 바뀌지 않는 것을 확인했다.

크론이 하는 일은 **이 순서**다(순서가 의미 있다):
1. **당월 청구 생성** — ACTIVE 계약 중 당월이 계약기간에 걸치는 것. 이미 있으면 건너뛴다(유니크 `[leaseId, year, month]` + P2002 흡수로 이중 방어)
2. **이월 정정** — 위 조건(기한 전 + 이월액 있음)에 맞는 청구만
3. **상태 재판정** — 모든 청구를 규칙대로 다시 판정해 **달라진 것만** 갱신(납부일 경과 → OVERDUE)
4. **만기 임박 알림** — 만기 90일 이내 ACTIVE 계약에 `CONTRACT_EXPIRY` MessageLog **계약당 1건**

> 청구 중복은 `@@unique([leaseId, year, month])` 가 DB 차원에서 막는다(P2002 도 흡수).
> **만기 알림 중복은 애플리케이션 레벨**(`(leaseId, kind)` 조회 후 생성)에서만 막는다 —
> `MessageLog` 에 해당 유니크가 없다. 하루 1회 크론 + 어드민 버튼에는 충분하지만, DB 보장이 필요하면
> 스키마에 `@@unique([leaseId, kind])` 추가가 필요하다(이 task 는 스키마를 건드리지 않았다).

환경변수는 [`.env.example`](../../.env.example) 의 `CRON_SECRET`·`NEXT_PUBLIC_WEB_URL` 참고 —
web·admin **두 앱에 같은 `CRON_SECRET`** 을 넣어야 어드민 버튼이 동작한다.


### T1.5 수납 UI — 내역 표시 · 납부 추가 · 상태 재계산

```ts
import { describeCharge, isOverpayment, resolveChargeStatus, sumPayments, kstToday } from "@/lib/rent";

// 청구 리스트/시트: 월세+관리비+이월+연체료 내역
const view = describeCharge(charge, kstToday());
view.lines;        // [{ key:"RENT", label:"월세", amount, paid }, …] 4줄
view.outstanding;  // 남은 금액
view.status;       // 배지

// 납부 추가 — 초과 납부는 400
if (isOverpayment(charge.totalDue, charge.paidAmount, body.amount)) return fail("VALIDATION_ERROR", …);

// 납부 추가·삭제 후 상태 재계산 (paidAmount 는 payments 합계가 원본)
const paidAmount = sumPayments(payments);
const status = resolveChargeStatus({ totalDue: charge.totalDue, paidAmount, dueDate: charge.dueDate, asOf: kstToday() });
await prisma.rentCharge.update({ where: { id }, data: { paidAmount, status } });
```

### T1.6 임대장부 — 월별·항목별 집계 (paidAt 기준)

```ts
import { allocatePayments, kstYearMonth } from "@/lib/rent";

for (const charge of charges) {
  for (const { payment, allocation } of allocatePayments(charge, charge.payments)) {
    const { year, month } = kstYearMonth(payment.paidAt);   // ★ 월 경계는 KST
    bucket(year, month).rent        += allocation.rent;
    bucket(year, month).maintenance += allocation.maintenance;
    bucket(year, month).lateFee     += allocation.lateFee;
    bucket(year, month).carriedOver += allocation.carriedOver;   // 이월분은 별도 항목
  }
}
```

`allocatePayments` 는 `paidAt` 오름차순으로 앞선 납부부터 충당한다. 각 행의 배분 합 = 그 납부액이다.

### T1.9 임대인 홈 대시보드

```ts
import { calcOutstanding, isExpiringWithin, kstToday, kstYearMonth, EXPIRY_NOTICE_DAYS } from "@/lib/rent";

// 연체 리스트·건수: status 필터를 쓴다 (부분납은 연체로 세지 않는다 — 상태 우선순위 참고)
const overdue = await prisma.rentCharge.findMany({ where: { status: "OVERDUE", … } });
const overdueAmount = overdue.reduce((s, c) => s + calcOutstanding(c.totalDue, c.paidAmount), 0);
// 시드 기준: 1건 / 1,015,000원

// 이번 달 수납 현황
const { year, month } = kstYearMonth();

// 만기 3개월 이내
const soon = leases.filter((l) => isExpiringWithin(l.endDate, kstToday(), EXPIRY_NOTICE_DAYS));
```

> **주의** — 대시보드의 "연체"는 `status === "OVERDUE"`(= 기한 경과 + **한 푼도 안 낸** 청구)다.

## 후속 task 가 알아야 할 것

- **`asOf` 는 항상 `kstToday()`** 를 넘긴다. `new Date()` 를 그대로 넘기면 UTC 자정~KST 자정 사이 9시간 동안 하루가 어긋난다.
- **`paidAmount` 의 원본은 `RentPayment` 합계**다. 납부 추가·삭제 후에는 `sumPayments` → `resolveChargeStatus` 로
  `paidAmount`·`status` 를 같이 갱신한다(T1.5). 크론은 상태만 고쳐 주고 `paidAmount` 는 손대지 않는다.
- **크론은 PENDING_TENANT 계약에 청구를 만들지 않는다**(ACTIVE 만). 시드 202호처럼 연결 전 계약에 청구가 필요하면
  T1.2 가 등록 시점에 `buildChargeDraft` 로 만든다.
- **크론은 당월 청구만 만든다.** 과거 누락 월을 소급 생성하지 않는다(데모에서 청구가 갑자기 불어나지 않게).
- **스키마는 변경하지 않았다.** `carriedOverAmount`·`lateFeeAmount`·`lateFeeRatePct`·`paymentDay` 는 이미 있었다.
- **어드민 `/cron` 화면에는 인증이 없다** — 어드민 앱 자체에 아직 로그인이 없어서다(T6.3 범위).
  시크릿은 서버 액션에서만 읽히므로 브라우저로 새어 나가지는 않지만, 어드민 URL을 아는 사람은 크론을 돌릴 수 있다.
  크론이 멱등이라 피해는 없지만 어드민 인증이 붙으면 이 화면도 그 뒤로 들어가야 한다.
- **[PHASES.md](../PHASES.md) 의 T1.4 상태(⬜)는 갱신하지 않았다** — 파일 소유권상 이 task 범위 밖이라
  Phase 1 통합 시점에 함께 ✅ 로 바꾼다.
