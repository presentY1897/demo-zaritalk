## 대중교통은 모킹 ([D9](../DECISIONS.md#-d9-대중교통-통근시간--모킹-2026-09-02-확정))

- **차량**: 카카오모빌리티 REST 실연동 (`KAKAO_REST_API_KEY` 설정 완료)
- **대중교통**: 모의 제공자. ODsay 키가 생기면 제공자 구현만 교체한다.
- 제공자를 인터페이스로 두고 `car`/`transit` 두 구현을 넣는다. 모의 값은 **화면에 모의임을 표시**하고, 좌표 기반 **결정적** 함수여야 한다 — 같은 (매물, 근무지) 쌍이 매번 같은 값을 내야 `CommuteCache` 와 테스트가 흔들리지 않는다.
- 카카오모빌리티 REST 에는 대중교통 경로 API 가 없다(자동차·도보만). 대중교통을 실연동하려면 ODsay 가 필요하다.

### T3.2·T3.3 이 만들어 둔 자리를 그대로 썼다

T3.2 는 "T3.5 가 할 일은 `POST /api/commute` 로 `CommuteCache` 를 채우는 것뿐 — 캐시 행이
생기면 표시 코드 변경 없이 켜진다" 고 남겨 뒀고, **그 계약대로 됐다.**
`features/listing/commute.ts` 는 여전히 **읽기 전용**이고 `readCommuteCache`·`readUnitCommutes`·
`readCommuteForUnit`·`resolveCommuteWorkplace` 의 시그니처도 그대로다.

고친 것은 **세 곳뿐**이고 전부 "채우는" 방향이다.

| 무엇 | 왜 |
|---|---|
| `ListingCommuteDto` 에 **`mockModes`** 한 칸 추가 | 대중교통이 모의라(D9) 화면이 그 사실을 밝혀야 한다. 나머지 필드는 손대지 않았다 |

## `POST /api/commute`

```jsonc
// 요청 — 좌표는 보내지 않는다
{ "unitId": "cmf0…", "workplaceId": "cmf0…" }
```

```jsonc
// 200
{
  "unitId": "cmf0…",
  "commute": {
    "workplaceId": "cmf0…", "workplaceLabel": "회사",
    "transitMinutes": 29,          // 한쪽만 성공했으면 다른 쪽은 null
    "drivingMinutes": 28,
    "fetchedAt": "2026-09-03T05:12:44.120Z",
    "mockModes": ["transit"]       // 모의 제공자로 채운 이동수단
  },
  "cached": false,                 // true 면 **외부 호출 0건**
  "failures": [                    // 값을 얻지 못한 이동수단(없으면 [])
    { "mode": "car", "reason": "RATE_LIMITED", "status": 429 }
  ]
}
```

| 실패 | status · code |
|---|---|
| 비로그인·만료 세션 | 401 `UNAUTHORIZED` |
| 세입자 프로필 없음(임대인 계정 등) | 403 `FORBIDDEN` |
| `unitId`·`workplaceId` 누락·빈 값·64자 초과 | 400 `VALIDATION_ERROR` |
| 없는 근무지 | 404 `NOT_FOUND` |
| **남의 근무지** | 403 `FORBIDDEN` |
| 없는 호실 · **매물이 한 번도 올라온 적 없는 호실** | 404 `NOT_FOUND` |
| 건물·근무지 좌표가 대한민국 범위 밖 | 400 `VALIDATION_ERROR` (외부 호출 없음) |
| **두 이동수단 모두 실패** | 500 `INTERNAL_ERROR` — 캐시를 만들지 않는다 |

- **본문에 좌표가 없다.** 출발지는 `Unit.building.lat/lng`, 도착지는 `Workplace.lat/lng` 를
  서버가 직접 읽는다 — 클라이언트가 좌표를 보내면 캐시 키(`unitId`·`workplaceId`)와 실제로
  계산한 지점이 어긋날 수 있고, 그 값이 남의 배지로도 쓰인다.
- **`GET` 을 두지 않았다.** 읽기는 이미 T3.2·T3.3 이 `GET /api/listings?workplaceId=`·
  `GET /api/listings/[id]?workplaceId=` 로 하고 있다. 여기는 "없으면 만든다" 라서 `POST` 다.
- **`refresh: true` 같은 강제 갱신 파라미터도 없다.** 클라이언트가 TTL 을 우회할 수 있으면
  캐시가 쿼터를 지켜 주지 못한다(누르는 만큼 외부로 나간다).
- 500 의 코드가 `INTERNAL_ERROR` 인 것은 `lib/api/response.ts` 의 `ApiErrorCode` 에 업스트림용
  코드(502 성격)가 없기 때문이다. 그 파일은 D1 공용 규약이라 이번 task 에서 넓히지 않았다.

### 왜 "매물이 있는 호실" 만 받나

통근시간은 **매물을 고르려고** 보는 값이다. 아무 `unitId` 나 받으면 남이 살고 있는 호실을 향한
계산을 시켜 캐시를 채울 수 있고, 그 호실이 존재하는지도 알려 주게 된다. 그래서 "매물이 하나라도
붙은 호실" 로 좁혔다. **상태(OPEN·RESERVED·CLOSED)는 보지 않는다** — `/listings/[id]` 는 예약·종료
매물도 열리고(T3.3), 그 화면에서 눌러도 되어야 한다.

### 남의 근무지에 403 을 주는 것은 공개 조회와 다르다

`GET /api/listings` 의 `workplaceId` 는 **조용히 무시**한다 — 비로그인도 부르는 공개
엔드포인트라 "그 id 의 근무지가 있다" 가 새면 안 되기 때문이다(T3.2). 반면 여기는 **로그인
세입자 전용 쓰기**라 T3.4 `requireOwnWorkplace` 규약(404·403)을 그대로 따른다.

## 제공자 인터페이스

```ts
export type CommuteProvider = {
  readonly mode: "transit" | "car";
  readonly mock: boolean;   // 화면의 「모의」 표시와 `*Detail.mock` 이 된다
  readonly name: string;    // "kakao-mobility" · "mock-transit"
  route(origin: CommutePoint, destination: CommutePoint): Promise<CommuteResult>;
};

type CommuteResult =
  | { ok: true; data: { minutes: number; distanceM: number | null; mock: boolean; detail: CommuteDetail } }
  | { ok: false; failure: { reason: CommuteFailureReason; status?: number | null; detail?: string } };
```

규약 세 가지 —

1. **던지지 않는다.** 실패는 `CommuteResult` 로 접어 돌려준다(부분 결과를 저장해야 하므로).
   그래도 던지면 `service.ts` 가 `UPSTREAM` 으로 접는다 — ODsay 구현이 들어올 때의 마지막 그물이다.
2. **`mock` 을 스스로 밝힌다.** 숨기면 데모를 보는 사람이 모의 값을 실측으로 오해한다.
3. **`detail` 은 그대로 `CommuteCache.transitDetail`·`drivingDetail`(Json)에 들어간다.**
   나중에 "이 값이 어디서 왔나" 를 되짚을 수 있어야 한다. 실패한 칸에도 사유를 남긴다
   (`{ provider, mock, failed: true, reason, status }`).

`service.ts` 는 두 제공자를 **`Promise.all` 로 나란히** 부른다 — 순서대로 부르면 자동차
타임아웃 6초가 대중교통 앞을 막는다.

### 카카오모빌리티 자동차 길찾기 — 실호출로 확인한 함정 3가지

[공식 문서](https://developers.kakaomobility.com/guide/navi-api/directions)

```
GET https://apis-navi.kakaomobility.com/v1/directions
    ?origin=127.03648,37.56152&destination=127.02762,37.49794&priority=RECOMMEND&summary=true
Authorization: KakaoAK <REST 키>
```

| 함정 | 무엇 |
|---|---|
| **좌표는 `경도,위도`(x,y)** | 우리 DB·DTO 는 전부 `lat, lng` 순이다. 뒤집으면 400 이 아니라 **엉뚱한 좌표로 200** 이 온다 — 조용한 오답이라 `buildKakaoDirectionsUrl` 한 곳에서만 조립하고 테스트가 그 함수를 직접 본다 |
| **`summary=true` 를 반드시** | 없으면 `sections[].roads[].vertexes` 에 경로 좌표가 통째로 실린다. 같은 요청이 **521B → 수백 KB** 였다 |
| **경로를 못 찾아도 HTTP 200** | 실패는 `routes[0].result_code` 로 온다(`0` 성공 · `1` 결과 없음 · `104` 출발·도착 5m 이내 …). status 만 보면 "성공했는데 값이 없는" 상태가 된다 |

응답에서 쓰는 값은 `summary.duration`(초 → 분 반올림, 최소 1분)과 `summary.distance`(m) 뿐이고,
`fare.taxi`·`fare.toll` 은 `drivingDetail` 에만 남긴다.

## 모의 대중교통 산식과 결정성

```
km = haversineKm(출발, 도착)          // lib/geo/distance.ts 재사용
1km 이하 → 도보:     분 = (km × 1.2) / 4.5km/h × 60
1km 초과 → 대중교통: 분 = (8 + (km × 1.35) / 27km/h × 60) × (1 + 흔들림)
흔들림 = coordSignal(출발, 도착) × 0.08          // -8% ~ +8%
```

| 상수 | 값 | 근거 |
|---|---|---|
| 접근·대기 | 8분 | 양쪽 도보 접근 + 승강장 대기·환승. 문 앞에서 바로 타지 않는다 |
| 표정속도 | 27km/h | 서울 지하철(≈32)과 시내버스(≈19)를 섞은 값 |
| 우회 배율 | 1.35 | 노선은 직선으로 놓이지 않는다 |
| 흔들림 | ±8% | 같은 거리라도 노선·환승 수에 따라 다르다 |
| 도보 분기 | 1km · 4.5km/h | 1km 안쪽에 「대중교통 20분」 이 뜨면 값이 거짓말이 된다 |

행당해피빌 → 강남역(직선 7.1km)이 **30분 안팎**으로 나온다. 같은 구간을 카카오모빌리티는
자동차 28분·도로 8.4km 로 준다(실호출). 실제 대중교통 40분대와 같은 자릿수다.

**결정성 보장** — 값이 `CommuteCache` 에 저장되므로 랜덤이면 캐시를 지웠다 채울 때마다 배지가
흔들리고 테스트가 값을 단언할 수 없다. 그래서

- 산식은 **좌표만의 함수**다. `Math.random()`·`Date.now()`·환경변수를 읽지 않는다.
- 흔들림은 좌표를 **소수 6자리(≈11cm)로 끊은 문자열의 FNV-1a 32bit 해시**다. 부동소수 끝자리가
  달라도 같은 지점이면 같은 값이 나온다.
- `transit.test.ts` 가 ①50번 불러도 같은 값 ②1e-9 만큼 흔든 좌표도 같은 값 ③캐시를 지웠다
  다시 채워도 같은 값(라우트 테스트)까지 못 박는다.

## 캐시 TTL 과 근거

| 행 | TTL | 근거 |
|---|---|---|
| 두 값이 다 있다 | **7일** | 이 값을 좌우하는 것은 도로망·노선이지 실시간 교통이 아니다. 우리는 "이 집이 저 집보다 가까운가" 라는 **비교용 상대값**으로 쓴다. 반대로 영원히 두면 도로 개통·노선 변경을 놓친다. 매물 하나당 근무지 5곳이라도 주당 5회다 |
| 한쪽이 비었다(부분 결과) | **1시간** | 빈 칸은 대개 일시적 실패(쿼터·타임아웃)다. 7일을 기다리면 그동안 자동차 값이 영영 안 뜬다. 그렇다고 즉시 재시도하면 장애가 난 동안 매 요청이 외부로 나간다 |

- 경계는 **만료**다(`now - fetchedAt < ttl`). 딱 7일이면 다시 계산한다.
- **부분 결과는 덮어쓴다.** 행에 `fetchedAt` 이 하나뿐이라 실패한 칸에 예전 값을 남기면
  "언제 기준" 이 거짓이 된다. 대신 부분 결과 TTL 이 짧아 곧 다시 채워진다.
- **양쪽 다 실패하면 행을 만들지 않는다.** 빈 행을 남기면 다음 요청이 "부분 결과" 로 착각해
  1시간을 기다린다.
- 조회를 **누른 근무지만** 부른다. 시트를 열자마자 근무지 5곳을 한꺼번에 부르면 여는 것만으로
  외부 호출이 5번 나간다.
- 근무지를 지우면 `CommuteCache` 도 사라진다(스키마 `onDelete: Cascade`) — T3.5 가 따로 지울 게 없다.

## 외부 호출 실패를 어떻게 다루나 — **화면은 죽지 않는다**

| 사유 | 언제 | 화면 |
|---|---|---|
| `NO_KEY` | 서버에 `KAKAO_REST_API_KEY` 가 없다 | 자동차 칸만 「자동차 조회 실패」, 대중교통은 그대로 |
| `UNAUTHORIZED` | 401·403 | 〃 |
| `RATE_LIMITED` | 429 | 〃 |
| `UPSTREAM` | 그 밖 4xx·5xx·JSON 아님 | 〃 |
| `NETWORK` | 네트워크 실패·**타임아웃 6초** | 〃 |
| `NO_ROUTE` | HTTP 200 인데 `result_code != 0` | 〃 |

- 실패는 **응답 `failures[]` 로 올라오고** `*Detail` 에도 남는다(`{ failed: true, reason }`).
- 사유별로 문구를 갈아 끼우지 않는다 — 사용자가 할 수 있는 일이 없다. 로그·트래킹용이다.
- **두 이동수단 모두 실패하는 경우는 대중교통이 모의인 동안 구조적으로 일어나지 않는다**
  (모의 제공자는 좌표만 보므로 실패하지 않는다). ODsay 를 붙이면 열리는 경로라
  `features/commute/service.test.ts` 가 실패하는 제공자를 주입해 미리 지킨다.
- 타임아웃 6초는 "사용자가 「조회」를 누르고 기다리는 시간" 기준이다. 넘기면 자동차만 실패하고
  대중교통 값은 그대로 저장된다.

    요청만 가로채므로 우리 **서버**가 부르는 카카오는 막을 수 없고, 반대로 `/api/commute`

    라우트가 **캐시 히트로 실제로 응답**하게 했다 — 외부 호출 0건으로 권한·조회·표시·배지가
    전부 진짜로 돈다. 캐시 미스 → 외부 호출 → upsert 경로는 Vitest 가 `fetch` mock 으로 덮는다.
  - **끝나면 등록한 근무지를 지운다.** E2E 는 시드 DB 를 모든 스펙이 이어서 쓰는데
    (`globalSetup` 이 한 번만 시드한다) `listing.spec.ts` E2E② 가 "시드 세입자의 근무지는 1곳"
    을 전제한다. 지우면 `CommuteCache` 도 cascade 로 함께 사라진다 — **기존 e2e 파일은 한 줄도
    고치지 않았다.**
  - 트래킹 단언은 **페이지를 떠나기 전에** 한다. 전송이 400ms 배치라, 바로 `goto` 로 전체
    새로고침을 하면 큐에 남은 이벤트가 `pagehide` 플러시 타이밍에 걸려 유실될 수 있다
    (실제로 한 번 겪었다).
