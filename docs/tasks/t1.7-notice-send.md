# T1.7 고지서 발송

> Phase 1 · 상태: ✅ · [Phase 구성](../PHASES.md)

| 라우트 | 화면·기능 |
|---|---|
| 발송 시트(`NoticeSendSheet`) | 종류 선택(월세/연체/만기) → 카톡 말풍선 스타일 미리보기(알림톡 모사) → 발송. **실제 SMS 없음**을 시트·화면에 명시 |
| `/landlord/messages` | 고지서 보내기(진행 중 계약 목록) + 발송 이력 — 수신번호·종류·시각·**열람 여부(openedAt)** |

| 엔드포인트 | 동작 |
|---|---|
| `GET /api/leases/[id]/notices` | 발송 시트가 쓸 계약 정보(세입자·건물·청구 목록) |
| `POST /api/leases/[id]/notices` | kind·대상 청구 지정, 템플릿 렌더, **token 발급**, MessageLog 생성 |
| `GET /api/landlord/messages` | 내 발송 이력 (`?leaseId=` 필터) |

**실제 알림톡·SMS 는 나가지 않는다.** 발송의 실체는 `MessageLog` 한 줄과 공개 고지서 링크(T1.8)다.

## `NoticeSendSheet` props 시그니처 (T1.2·T1.5 접합용)

```ts
// apps/web/src/features/notice/NoticeSendSheet.tsx
export type NoticeSendResult = { message: MessageLogDto; noticeUrl: string };

export type NoticeSendSheetProps = {
  /** 시트 열림 여부 */
  open: boolean;
  /** 닫기(딤·ESC·닫기 버튼·발송 완료 후 닫기에서 모두 호출된다) */
  onClose: () => void;
  /** 고지서를 보낼 계약. null 이면 아무것도 그리지 않는다 */
  leaseId: string | null;
  /** 처음 선택돼 있을 종류. 기본 "RENT_NOTICE" */
  defaultKind?: NoticeKind;                 // "RENT_NOTICE" | "OVERDUE_NOTICE" | "CONTRACT_EXPIRY"
  /** 처음 선택돼 있을 청구. 없으면 미납이 남은 최신 청구를 고른다 */
  defaultChargeId?: string;
  /** 호출부가 이미 계약 정보를 들고 있다면 넘긴다(재조회 생략) */
  initialTarget?: NoticeTargetDto;
  /** 발송 성공 시 — 이력 갱신(쿼리 무효화)은 훅이 알아서 한다 */
  onSent?: (result: NoticeSendResult) => void;
};

export function NoticeSendSheet(props: NoticeSendSheetProps): JSX.Element | null;
```

```tsx
// 계약 상세(T1.2) / 청구 시트(T1.5) 에서
const [open, setOpen] = useState(false);

<Button onClick={() => setOpen(true)}>고지서 보내기</Button>
<NoticeSendSheet
  open={open}
  onClose={() => setOpen(false)}
  leaseId={lease.id}
  defaultKind="OVERDUE_NOTICE"   // 선택
  defaultChargeId={charge.id}    // 선택
/>
```

- **필요한 건 `leaseId` 하나뿐이다.** 세입자·건물·청구 목록은 시트가 `GET /api/leases/[id]/notices` 로
  스스로 읽는다(`open` 일 때만). 이미 들고 있으면 `initialTarget` 으로 넘겨 재조회를 아낀다.
- 발송 성공 시 `["notice","messages"]` 쿼리를 무효화하므로 이력 화면이 저절로 갱신된다.
  계약 화면의 자체 쿼리는 `onSent` 에서 직접 무효화하면 된다.
- 시트 안의 `data-testid`: `notice-kind-<KIND>` · `notice-charge-<chargeId>` · `notice-memo` ·
  `notice-preview` · `notice-send-submit` · `notice-sent` · `notice-sent-link`.

## 템플릿 3종

`renderNoticeTemplate()` 하나가 **발송과 미리보기에 같이 쓰인다** — 미리보기와 실제 본문이 어긋날 수 없다.
0원 항목은 문구에서 빠지고, 부분납이면 "이미 납부 / 남은 금액"이 붙는다. 메모는 본문 끝에 붙는다.

| kind | 제목 | 본문 뼈대 |
|---|---|---|
| `RENT_NOTICE` | `2026년 9월 월세 고지서` | 인사 → 항목별 금액 → **납부하실 금액** → 납부기한(D-n) → 입금 계좌 |
| `OVERDUE_NOTICE` | `2026년 8월 월세 연체 안내` | 인사(N일째 미납) → 항목별 금액(이월·연체료 포함) → **미납 금액** → 기한(N일 경과) → 계좌 → "이미 납부하셨다면…" |
| `CONTRACT_EXPIRY` | `임대차 계약 만기 안내 (2027년 2월 28일)` | 인사 → 계약 기간 → 만기까지 N일 → 월세·관리비·납부일 → 재계약 안내 (청구 없음) |

```text
[자리톡] 2026년 8월 월세 연체 안내

박세입님, 행당해피빌 201호 2026년 8월분 월세가 27일째 미납 상태입니다.

· 월세 650,000원
· 관리비 50,000원
· 전월 이월 300,000원
· 연체료 15,500원
─────────────
미납 금액 1,015,500원
납부기한 2026년 8월 5일 (27일 경과)

입금 계좌
자리은행 1002-0917-2026 (예금주 김임대)

이미 납부하셨다면 이 안내는 무시하셔도 됩니다.
```

- **공개 고지서 링크는 본문에 넣지 않는다.** 토큰은 발송 시점에 정해지고 링크는
  `noticeUrl(base, token)` 으로 언제든 만들 수 있다. 본문(`MessageLog.body`)을 순수하게 두면
  공개 고지서 페이지가 그대로 "임대인이 보낸 안내"로 보여 줄 수 있고 스냅샷도 안정적이다.
  말풍선 미리보기는 알림톡의 링크 버튼 자리를 따로 그린다.
- **납부 계좌는 데모용 더미 상수**(`DEMO_BANK_ACCOUNT`)다. 예금주만 임대인 이름으로 채운다 —
  스키마에 계좌 필드가 없다(아래 "스키마" 참고).

## 토큰

- `MessageLog.token` 은 `@unique`. **128비트 난수 32자 hex**(`crypto.randomUUID`)로 발급한다 —
  토큰만 알면 비로그인으로 청구 내역이 열리므로 계약 id·순번처럼 추측 가능한 값을 쓰지 않는다.
- 유니크 충돌은 사실상 나지 않지만, 나더라도 발송이 실패하지 않게 **최대 3회 재발급**(P2002 흡수).
- 시드의 사람이 읽는 토큰(`demo-notice-hong`)도 형식 검사(`isNoticeTokenShape`)를 통과한다 —
  데모 고정 링크용 예외다.

## 뒤 task 가 알아야 할 것

- **T1.2(계약 상세)·T1.5(청구 시트)**: 위 props 그대로 `NoticeSendSheet` 를 꽂으면 된다.
  `/landlord/messages` 로 가는 링크도 두 화면(또는 T1.9 홈)에 붙여 주면 좋다 — **탭바에는 없는 경로**다
  (T0.5 탭 배정표를 건드리지 않았다).
- **계약 소유권 가드**는 `features/notice/guards.ts` 의 `requireOwnedLease` 에 있다.
  T1.2 가 `features/landlord/ownership.ts` 에 같은 헬퍼를 만들었다면 **머지 때 그쪽으로 합치고 이 파일을 지운다**
  (동시 작업 중이라 T1.1 소유 파일을 건드리지 않았다).
- **스키마는 변경하지 않았다.** 필요했지만 만들지 않은 것 둘:
  1. **임대인 계좌** — `Profile`/`LandlordDetail` 에 은행·계좌번호 필드가 없어 `DEMO_BANK_ACCOUNT` 상수로 뒀다.
  2. **발송 멱등 제약** — `MessageLog` 에 `@@unique([leaseId, chargeId, kind])` 같은 제약이 없어
     같은 청구에 고지서를 여러 번 보낼 수 있다(의도적으로 허용 — 재발송이 필요하다). 재발송을 막아야 하면 스키마가 필요하다.
- **`MessageLog.body` 는 발송 시점의 스냅샷**이다. 이후 납부가 생겨도 본문은 바뀌지 않는다
  (공개 고지서 페이지의 금액 카드는 반대로 **조회 시점 재판정값**을 보여 준다 — 둘의 역할이 다르다).
