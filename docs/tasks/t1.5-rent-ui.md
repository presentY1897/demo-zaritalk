## 금액은 전부 원장 엔진이 계산한다

`features/lease/queries.ts` 한 곳에서만 [T1.4](./t1.4-rent-engine.md) 함수를 부르고, 화면·API 는 그 결과만 그린다.

| 쓰는 곳 | 함수 | 무엇을 얻나 |
|---|---|---|
| `toChargeDto` | `describeCharge(charge, kstToday())` | `lines`(4줄) · `totalDue` · `outstanding` · `excess` · `status` · `overdueDays` |
| `toLeaseChargeSummary` | `resolveChargeStatus` · `calcOutstanding` | 계약 단위 미납 건수·합계·연체 건수 |
| `recalcCharge` | `sumPayments` → `resolveChargeStatus` | 납부 추가·삭제 후 `paidAmount`·`status` |
| `POST …/payments` | `isOverpayment` · `calcOutstanding` | 초과 납부 400 판정과 안내 문구 |
| `POST /api/leases`(T1.2) | `buildChargeDraft` | 등록 시 당월 청구 |

- **`asOf` 는 언제나 `kstToday()`** 다. 응답의 `status`·`outstanding`·`overdueDays` 는 **저장된 컬럼이 아니라 엔진이 다시 판정한 값**이라, 크론이 하루 1회 상태를 맞추기 전이라도 화면은 곧바로 연체로 보인다.
- 표시 순서는 **월세 → 관리비 → 전월 이월 → 연체료**(`CHARGE_LINE_ORDER`), 충당 순서는 **이월 → 연체료 → 관리비 → 월세**(`ALLOCATION_ORDER`) — 둘은 다르다.
- 상태 라벨·배지 tone 은 `features/lease/status.ts` 한 곳에서만 정한다: 완납 `success` · 부분납 `warning` · 연체 `danger` · 예정 `neutral`. 색만으로 뜻을 전하지 않게 배지에 항상 라벨을 함께 넣는다(T0.6).

## 납부 추가·삭제 시 상태 재계산 흐름

`RentCharge.paidAmount` 는 비정규화 컬럼이고 **원본은 `RentPayment` 합계**다. 크론(T1.4)은 상태만 고쳐 주고 `paidAmount` 는 손대지 않으므로, 납부가 바뀔 때마다 아래 한 경로(`recalcCharge`)로 **둘을 함께** 갱신한다.

```
POST /api/charges/[id]/payments          DELETE /api/payments/[id]
  ├ requireLandlord → requireOwnedCharge   ├ requireLandlord → requireOwnedPayment
  ├ zod (amount>0, method 2종, memo)       ├ method === CARD → 409 (T2.2 소유)
  ├ isOverpayment(...) → 400               ├ prisma.rentPayment.delete
  ├ prisma.rentPayment.create              │
  └───────────────┬─────────────────────────┘
                  ▼
        recalcCharge(chargeId)                     ← features/lease/queries.ts
          paidAmount = sumPayments(payments)
          status     = resolveChargeStatus({ totalDue, paidAmount, dueDate, asOf: kstToday() })
          변한 게 없으면 UPDATE 하지 않는다
          → 갱신된 ChargeDto 반환 (호출부가 다시 읽을 필요 없음)
```

- 상태 우선순위는 엔진 규칙 그대로 `PAID > PARTIALLY_PAID > OVERDUE > SCHEDULED`. 완납 → 납부 취소 → **부분납**, 전부 취소 → 기한이 지났으면 **연체**로 되돌아간다.
- 클라이언트는 납부 성공 시 청구·계약 캐시와 함께 **자산 캐시(`landlordKeys.building`·`unit`·`buildings`)** 도 무효화한다(`features/lease/hooks.ts` 의 `PaymentScope`). 청구 상태가 바뀌면 호실 그리드의 연체 색도 달라지는데, 쿼리 기본 `staleTime` 이 30초라 무효화하지 않으면 자산 화면이 옛 색을 그대로 보여 준다.

### `GET /api/leases/[id]/charges`

```jsonc
// 200 — 최신 월부터. lines 는 항상 4줄(0원 포함, 화면에서 0원 줄은 숨긴다)
{
  "charges": [
    {
      "id": "cmf0…", "leaseId": "cmf0…", "year": 2026, "month": 8,
      "dueDate": "2026-08-05",
      "rentAmount": 650000, "maintenanceAmount": 50000,
      "carriedOverAmount": 300000, "lateFeeAmount": 15500,
      "totalDue": 1015500, "paidAmount": 0,
      "outstanding": 1015500, "excess": 0,
      "overdueDays": 27, "status": "OVERDUE",
      "lines": [
        { "key": "RENT",        "label": "월세",      "amount": 650000, "paid": 0 },
        { "key": "MAINTENANCE", "label": "관리비",    "amount": 50000,  "paid": 0 },
        { "key": "CARRY_OVER",  "label": "전월 이월", "amount": 300000, "paid": 0 },
        { "key": "LATE_FEE",    "label": "연체료",    "amount": 15500,  "paid": 0 }
      ],
      "payments": [
        { "id": "cmf0…", "chargeId": "cmf0…", "amount": 400000,
          "method": "MANUAL_CHECK", "paidAt": "2026-07-10T00:00:00.000Z", "memo": "일부 입금 확인" }
      ]
    }
  ]
}
```

401 `UNAUTHORIZED` / 404 없는 계약 / 403 타인 계약.

### `POST /api/charges/[id]/payments`

```jsonc
// 요청 — 「받음 체크」는 MANUAL_CHECK(금액만), 「가상 입금」은 VIRTUAL_TRANSFER(memo = 입금자명)
{ "amount": 1015500, "method": "VIRTUAL_TRANSFER", "memo": "박세입" }
// 201 — 재계산이 끝난 청구를 그대로 돌려준다(화면이 다시 읽지 않아도 된다)
{
  "charge": { …ChargeDto…, "paidAmount": 1015500, "outstanding": 0, "status": "PAID" },
  "payment": { "id": "cmf0…", "amount": 1015500, "method": "VIRTUAL_TRANSFER", "memo": "박세입", … }
}
```

| 실패 | status · code |
|---|---|
| **초과 납부**(남은 금액 초과) | 400 `VALIDATION_ERROR` — `"남은 금액(300,000원)을 넘겨 받을 수 없습니다."` |
| `amount` 가 0·음수·정수 아님, `method` 가 `CARD`·모르는 값 | 400 `VALIDATION_ERROR` |
| 비로그인 / 없는 청구 / 타인 청구 | 401 / 404 / 403 |

`paidAt` 은 받지 않는다 — 임대인이 과거 시각을 임의로 적으면 장부(T1.6)의 월 집계(`kstYearMonth(paidAt)`)가 흔들린다.

### `DELETE /api/payments/[id]`

```jsonc
// 200 — D1 규약의 204 대신 갱신된 청구를 준다(상태 배지·잔액을 곧바로 다시 그려야 한다)
{ "charge": { …ChargeDto…, "paidAmount": 400000, "outstanding": 300000, "status": "PARTIALLY_PAID" } }
```

| 실패 | status · code |
|---|---|
| 비로그인 / 없는 납부 / 타인 납부 | 401 / 404 / 403 |
| **`CARD`(자리페이) 납부** | 409 `CONFLICT` — 토스 취소와 함께 다뤄야 한다(T2.2) |
