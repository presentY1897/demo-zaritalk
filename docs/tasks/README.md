## 테스트 전략 ([D8](../DECISIONS.md#-d8-테스트-스택) 결정 대기)

- **최소 테스트 = Vitest 단위·API 테스트.** 순수 로직(원장 규칙, 환급 계산, 반경 매칭, A/B 배정)은 함수 단위로. Route Handler는 Request 객체로 직접 호출해 검증. DB가 필요한 테스트는 로컬 Postgres의 테스트 전용 DB(`zari_test`)에서 truncate 격리.
- **통합 테스트 = Playwright E2E.** Phase별 핵심 사용자 여정 1~2개만 시드 데이터 기반으로. CI에서 빌드 후 실행.
- **외부 API**(토스·카카오·ODsay·국토부)는 단위 테스트에서 mock. E2E는 토스 테스트모드만 실호출, 나머지는 키 없으면 skip 태그.
- 커버리지 %를 목표로 하지 않는다. 대신: **돈·상태 전이가 걸린 로직은 반드시 단위 테스트, Phase별 핵심 여정은 반드시 E2E** — 이 두 줄이 기준.

## 공통 완료 기준 (모든 task에 적용)

1. `pnpm build`·`pnpm typecheck`·`pnpm test` 통과 (CI green)
2. 시드 데이터만으로 해당 화면·API가 동작 (별도 수동 세팅 불필요)
3. 웹 화면은 480px 모바일 셸 기준 확인, 어드민은 데스크톱 기준
4. 해당되는 경우 트래킹 이벤트(`<domain>_<object>_<action>`) 심기
5. 관련 스펙 파일(`docs/specs/`)의 상태줄·본문 갱신, task 상태 갱신
