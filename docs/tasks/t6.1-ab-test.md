## 해시 배정 — 왜 난수가 아닌가

```ts
bucket  = FNV1a32_avalanche(`${experimentKey}:${anonId}`) % 10_000
variant = 가중치 구간에 bucket 을 떨어뜨린 값        // 50:50 이면 0~4999 = A, 5000~9999 = B
```

- **결정성**: 같은 anonId 는 언제 어디서 계산해도 같은 변형이다. DB 를 읽지 않고도 값이 나온다.
- 난수 배정은 "같은 사람 = 같은 변형" 이 **DB 한 줄에만** 걸린다. 그 줄이 사라지거나(데이터 정리)
  쓰기가 실패하면 사람이 변형 사이를 오간다. 해시면 `AbAssignment` 는 *진실*이 아니라
  **"언제 처음 노출됐고 어느 계정과 이어졌는지" 를 남기는 기록**이다.
- **씨앗에 실험 키를 섞는다.** anonId 만 해싱하면 실험이 둘 이상일 때 한 사람이 모든 실험에서
  같은 쪽에 몰려 실험끼리 교란된다. 키를 섞으면 독립적이다(실측: 두 실험이 같은 변형일 확률 49.5%).
- 암호학적 해시가 아니다 — anonId 는 인증 수단이 아니라 "이 브라우저" 라벨이라 예측 가능해도
  권한이 따라오지 않는다. 대신 **의존성 0 · 순수 산술**이라 Node 버전·플랫폼에 상관없이 같은 값이다.

### 분포 실측

| 표본 | A | B |
|---|---|---|
| 32자 hex anonId 100,000개 (`notice_cta`) | **49.94%** | 50.06% |
| 같은 표본, 다른 실험 키 | 50.20% | 49.80% |
| 단위 테스트(20,000개, 매 실행 새 UUID) | 48~52% 안 | — |

단위 테스트는 매번 새 난수 anonId 로 재고, 허용 오차 ±2%p 다(20,000 표본의 3σ ≈ ±1.06%p).

### 이미 배정된 사람은 가중치를 바꿔도 안 움직인다

`AbAssignment` 에 줄이 있으면 **저장된 변형을 그대로 쓴다**. 실험 도중 가중치를 바꿨을 때
사람의 화면이 바뀌면 그 사람의 전환이 어느 변형의 성과인지 말할 수 없다.
(예외: 저장된 값이 실험 정의에 더 이상 없는 변형이면 다시 배정한다.)

## `?variant=` 강제 경로 — **남겼다. 대신 실험을 오염시키지 못하게 했다**

| 대안 | 왜 안 골랐나 |
|---|---|
| 지운다 | 데모 시연에서 반대 안을 보여 줄 방법이 사라진다. E2E 도 배정 운에 맡겨야 한다 |
| 남기되 배정까지 덮어쓴다 | 시연·QA 클릭이 실제 배정을 바꿔 **자기선택 편향**이 생긴다. 퍼널 숫자가 거짓말을 한다 |
| **(채택) 남기되 화면만 바꾸고, 어긋난 이벤트는 세지 않는다** | 시연은 되고 지표는 안 흔들린다 |

```ts
// app/(app)/notice/[token]/page.tsx — T6.1 이 갈아 끼운 한 줄
const assigned = isAnonId(anonId) ? await assignVariant(anonId, NOTICE_CTA_EXPERIMENT) : null;
const variant  = previewNoticeCtaVariant(variantParam) ?? resolveNoticeCtaVariant(assigned?.variant);
```

- `?variant=B` 는 **화면만** 바꾼다. `AbAssignment` 는 해시가 정한 값 그대로다(줄을 건드리지 않는다).
- 노출·클릭 이벤트의 `props.variant` 는 **화면에 실제로 그려진 값**이다. 그래서 미리보기로 만든
  이벤트는 배정과 어긋나고, [T6.2 퍼널](./t6.2-metrics.md)이 **어긋난 이벤트를 세지 않는다**
  (`funnel.totals.mismatchedEvents` 로 몇 건이 빠졌는지 화면에 드러난다).
- 이 규칙은 미리보기만 막는 것이 아니다 — 방문자가 주소창에서 쿼리를 바꿔도 지표가 흔들리지 않는다.
- anonId 쿠키가 없는 요청(형식이 깨진 값 등)은 배정 없이 대조군 A 를 그린다. proxy 가 첫 요청에
  쿠키를 심고 **같은 요청의 헤더에도 넣어 주므로**(T0.7) 정상 경로에서는 첫 화면부터 배정이 있다.

## API 요청·응답

에러는 [D1](../DECISIONS.md#-d1-api-스타일) 규약대로 `{ "error": { "code", "message" } }` 한 형태다.

### `GET /api/ab/notice_cta`

**비로그인 공개다.** 실험 대상이 미가입 세입자(공개 고지서 방문자)라 세션을 요구할 수 없고,
응답에 개인정보가 없다("이 브라우저가 어느 문구를 볼 것인가" 뿐).

```jsonc
// 200
{
  "experiment": {
    "key": "notice_cta",
    "name": "공개 고지서 가입 CTA",
    "description": "미가입 세입자가 보는 고지서 하단 CTA 의 문구·배치 2안 (D2)",
    "variants": [
      { "key": "A", "label": "A · 하단 카드(대조군)", "weight": 50 },
      { "key": "B", "label": "B · 상단 배너 + 하단 카드", "weight": 50 }
    ]
  },
  "assignment": {
    "anonId": "3f8a…32자hex",
    "variant": "B",
    "userId": null,               // 로그인 상태로 부르면 계정 id
    "assignedAt": "2026-09-03T04:12:00.000Z",
    "created": true               // 이번 호출에서 처음 만들어졌는가
  }
}
```

| 실패 | status · code |
|---|---|
| 등록되지 않은 실험 키 · 형식이 아닌 키 | 404 `NOT_FOUND` |

- anonId 는 `POST /api/track`·`GET /api/notices/[token]`(T0.7·T1.8)과 **같은 규칙**으로
  ① 쿠키 ② 서버 발급 순으로 정하고, ②였으면 응답에 `Set-Cookie` 를 실어 다음 요청부터 이어지게 한다.
- 로그인 상태로 부르면 배정에 `userId` 를 잇는다 — **비어 있을 때만**. 한 번 붙은 계정은
  덮어쓰지 않는다(공용 브라우저에서 뒷사람이 앞사람의 배정을 가로채지 않게).
- 공개 고지서 화면은 이 엔드포인트를 거치지 않고 서버에서 `assignVariant` 를 직접 부른다 —
  왕복을 하나 줄이고, 첫 페인트에 이미 변형이 정해져 있어야 CTA 가 깜빡이지 않는다.
  이 엔드포인트는 **클라이언트에서 배정을 물어야 하는 화면·진단·E2E** 를 위한 것이다.

### 동시 요청·쓰기 실패

- 같은 브라우저에서 두 요청이 동시에 오면 `create` 하나가 유니크 제약(`@@unique([anonId, experimentKey])`)에
  걸린다. 그때는 다시 읽어 이미 만들어진 줄을 쓴다 — 어느 쪽이 이겨도 값은 해시로 같다.
- DB 쓰기가 아예 실패해도 **계산된 변형을 그대로 돌려준다**(`persisted: false`).
  미가입 세입자가 보는 화면이 기록 실패로 죽으면 안 된다.

> **기존 E2E 를 한 곳 고쳤다** — `e2e/notice.spec.ts` E2E① 의
> `expect(ctaRows[0]?.props.variant).toBe("A")`. 배정이 실제 해시로 바뀌면서 컨텍스트마다 발급되는
> anonId 에 따라 A·B 가 갈리므로 값을 못 박을 수 없다. **"이벤트에 실린 변형 == `AbAssignment` 의 변형"**
> 을 확인하는 쪽으로 바꿨다(배정 줄이 한 줄 생기는지도 함께 본다).
