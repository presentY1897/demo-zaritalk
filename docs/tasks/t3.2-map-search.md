## `bounds` 형식과 검증

```
GET /api/listings?bounds=37.5432,127.0211,37.5721,127.0512
```

**`swLat,swLng,neLat,neLng`** — 남서 → 북동 순서로 위도·경도 네 개를 콤마로 잇는다.
카카오맵 `map.getBounds()` 가 주는 `LatLngBounds` 가 `getSouthWest()`·`getNorthEast()` 두
꼭짓점이라 그대로 옮겨 담을 수 있고, JSON 을 URL 에 싣는 것보다 짧다(지도를 움직일 때마다 나가는
쿼리라 길이가 그대로 로그·캐시 키 비용이다).

| 거절 조건 | status |
|---|---|
| 숫자가 4개가 아님 (`37.55,127.02,37.575`) | 400 `VALIDATION_ERROR` |
| **빈 칸** (`37.55,,37.575,127.05`) — `Number("")` 은 0 이라 조용히 다른 영역이 된다 | 400 |
| 숫자가 아님 · 위도 ±90 / 경도 ±180 밖 | 400 |
| 남서 ≥ 북동 (뒤집힘·0 크기) | 400 |
| `?bounds=` (빈 값) | 400 — **필터를 끄려면 파라미터를 빼야 한다** |

- **대한민국 범위(`features/address/coords.ts`)로는 막지 않는다.** 그 스키마는 "사용자가
  저장하는 지점" 을 막는 것이고, 여기는 화면이 보고 있는 영역이다. 바다 쪽으로 조금만 밀어도
  영역 모서리는 한국 밖으로 나가므로 범위로 막으면 정상 조작이 400 이 된다.
- **최대 크기 제한도 없다.** "전국이 보이게 축소" 는 정상 조작이다. 대신 `limit` 으로 자르고
  `truncated: true` 를 실어 화면이 "지도를 확대해 주세요" 로 안내한다.
- `bounds` 는 **선택**이다. 없으면 영역 제한 없이 최신순으로 준다 — `/search` 첫 진입은 지도가
  아직 어디를 보는지 모른다.
- 경계는 **포함**이다(`gte`/`lte`). 화면 쪽 `withinBounds` 와 같은 규칙이어야 "지도에는
  보이는데 목록에 없다" 가 생기지 않는다. 테스트가 네 모서리를 못 박는다.

## 필터 형식 — `filters=<JSON>` 이 아니라 평평한 파라미터

```
?dealType=WOLSE&depositMin=0&depositMax=20000000&rentMin=0&rentMax=700000&limit=100
```

task 표에는 `?bounds=&filters=` 라고만 적혀 있었다. JSON 을 한 파라미터에 우겨넣으면 ①URL 이
길어지고 ②`parseQuery`(D1 공용 헬퍼)를 그대로 못 쓰며 ③주소창에 남은 필터를 사람이 읽을 수 없다.
그래서 **필드마다 파라미터 하나**로 폈다 — `GET /api/posts`(T4.1)와도 같은 모양이다.

| 파라미터 | 값 | 비고 |
|---|---|---|
| `dealType` | `JEONSE` \| `WOLSE` | 없으면 전체 |
| `depositMin` · `depositMax` | **원 단위 정수** | 화면 칩은 "1,000만원 이하" 로 말하지만 파라미터는 언제나 원이다(`Listing.deposit` 이 원 단위 `Int`) |
| `rentMin` · `rentMax` | 원 단위 정수 | |
| `limit` | 1~200 (기본 100) | |
| `workplaceId` | 근무지 id | 통근 배지(T3.5 자리) |

- 숫자는 **정규식으로 모양을 먼저 본다**(`/^\d{1,13}$/`). `z.coerce.number()` 만 쓰면
  `?depositMax=` 가 **0** 으로 읽혀 "보증금 0원 이하" 라는 조용한 오답이 된다. 빈 값·소수점·문자는 400.
- `depositMin > depositMax`(월세도 같다)면 400 이고 문구가 어느 쪽인지 밝힌다.
- **전세는 `monthlyRent === 0`** 이다(T3.1 스키마가 강제한다). 그래서 `rentMin > 0` 을 걸면
  전세가 자동으로 빠지고, `rentMax` 만 걸면 전세도 함께 남는다. 별도 규칙이 아니라 데이터의
  성질이라 필터 시트에도 그대로 적어 뒀다.

## `GET /api/listings` 응답

```jsonc
// 200 — 세션을 요구하지 않는다
{
  "listings": [
    {
      "id": "cmf0…", "unitId": "cmf0…",
      "dealType": "WOLSE", "deposit": 10000000, "monthlyRent": 500000, "status": "OPEN",
      "priceLabel": "월세 1,000만/50만",   // 카드·상세가 쓰는 문자열
      "pinLabel": "월 50만",               // 지도 핀이 쓰는 짧은 문자열
      "description": "역까지 도보 5분", "photo": "https://…", "photoCount": 3,
      "availableFrom": "2026-11-01", "createdAt": "2026-09-02T…",
      "unit": { "id": "cmf0…", "label": "101호", "floor": 1, "areaM2": 23.1, "rooms": 1 },
      "building": { "id": "cmf0…", "name": "행당해피빌", "address": "서울 성동구 행당동 347",
                    "roadAddress": "서울 성동구 행당로 79", "lat": 37.56152, "lng": 127.03648 },
      "commute": null                      // T3.5 자리 — 캐시 히트일 때만 채워진다
    }
  ],
  "count": 1,
  "truncated": false,      // limit 에 걸려 잘렸는가
  "limit": 100,
  "bounds": { "swLat": 37.5432, "swLng": 127.0211, "neLat": 37.5721, "neLng": 127.0512 },
  "filters": { "dealType": "WOLSE", "depositMin": null, "depositMax": 20000000,
               "rentMin": null, "rentMax": 700000 },
  "commuteWorkplaceId": null // 통근 배지가 실제로 적용된 근무지. 무시됐으면 null
}
```

- **`status = OPEN` 만** 나간다. T3.1 의 `LISTING_STATUS_META.OPEN.description` 이 이미
  "매물 탐색에 노출됩니다" 라고 적어 뒀고, 예약(`RESERVED`)·종료(`CLOSED`)는 여기 뜨지 않는다.
- 좌표는 매물이 아니라 **건물**의 것이다(`Listing.unit.building.lat/lng`) — 매물에는 좌표가 없다.
- 정렬은 `createdAt desc, id desc`. 마지막 키를 `id` 로 둔 것은 같은 밀리초에 들어온 두 매물의
  순서가 요청마다 뒤집히지 않게 하기 위해서다(T4.1 커서 규약과 같은 이유).
- 응답에 **등록자 이름이 없다**(T3.3 문서의 "공개 화면이 담지 않는 것" 참고).
- `priceLabel`·`pinLabel` 을 **서버가 만들어 보낸다** — 핀과 카드가 다른 문자열을 보여 주면
  "핀에서 본 그 집" 인지 알 수 없다. `features/listing/price.ts` 한 곳에서 나온다.

### 커서 페이지네이션을 두지 않은 이유

지도 탐색에서 "다음 페이지" 는 뜻이 약하다. 결과가 많을 때 사용자가 하는 행동은 **지도를 좁히는
것**이지 더 읽는 것이 아니다. 그래서 `limit`(기본 100 · 최대 200)까지만 주고 잘렸다는 사실을
`truncated` 로 알려 화면이 "지도를 확대하면 빠짐없이 볼 수 있어요" 를 띄운다.
(T4.1 커뮤니티는 반대로 무한 스크롤이 자연스러워 커서를 뒀다 — 화면 성격이 다르다.)
`limit + 1` 을 읽어 한 번의 조회로 판정한다.

## 지도 이동마다 재조회하지 않는 방법 (4겹)

| 겹 | 무엇 | 어디 |
|---|---|---|
| 1 | 카카오 **`idle`** 이벤트만 듣는다 — 끌기·확대가 **끝난 뒤 한 번** | `KakaoMap.tsx` |
| 2 | **350ms 디바운스** — 멈췄다 다시 끄는 동작을 한 번으로 접는다 | `MapSearchView.tsx` |
| 3 | **이미 받아 온 영역 안이면 서버에 묻지 않는다**(`needsRefetch`) — 화면에 보이는 것만 `withinBounds` 로 골라 낸다 | `bounds.ts` |
| 4 | 물어야 하면 **화면보다 25% 넓게**(`expandBounds`) 받아 다음 팬을 미리 덮고, 좌표를 소수 4자리(≈11m)로 끊어(`roundBounds`) 손 떨림 수준의 이동이 **같은 캐시 키**가 되게 한다 | `bounds.ts` · `hooks.ts` |

- `center_changed`·`dragend` 를 쓰지 않은 이유: 끌기 **도중에도** 계속 불린다. `idle` 은 멈춘
  뒤 한 번이라 재조회 횟수가 "이동 횟수" 가 아니라 "멈춘 횟수" 가 된다.
- 3번이 핵심이다. 넓게 받아 뒀으므로 짧은 팬은 **네트워크 0** 이고, 리스트는 클라이언트에서
  화면 영역으로 다시 걸러 지도와 항상 같은 것을 보여 준다.
- 직전 응답이 잘렸으면(`truncated`) 안쪽으로 들어가도 다시 묻는다 — 그 영역에 못 받은 매물이 있다.
- Tanstack Query 는 `keepPreviousData`(깜빡임 방지)와 `staleTime` 30초(왔다 갔다 하는 팬)를 더한다.
- 규칙은 전부 **순수 함수**라 DB 없이 테스트한다(`features/search/bounds.test.ts`).

## 지도 SDK 를 어떻게 넣었나 — `next/script` + `autoload=false`

```
https://dapi.kakao.com/v2/maps/sdk.js?appkey=<NEXT_PUBLIC_KAKAO_MAP_JS_KEY>&autoload=false
```

카카오 공식 문서(`apis.map.kakao.com/web/documentation/` → `kakao.maps.load`)가 못박은 규칙이다:

> v3 스크립트를 동적으로 로드하기 위해 사용한다. … v3 로딩 스크립트 주소에 파라메터로
> `autoload=false` 를 지정해 주어야 한다. `kakao.maps.load(callback)`

즉 **`autoload=false` 를 붙이고 `kakao.maps.load(콜백)` 안에서** 객체를 만들어야 한다.
스크립트가 다 내려오기 전에 `kakao.maps.Map` 을 만지면 에러가 난다.

Next 16 에서 그 자리는 **`next/script` 의 `onReady`** 다 — 공식 Next 문서
(`node_modules/next/dist/docs/01-app/03-api-reference/02-components/script.md`)의 Google Maps
예제가 정확히 같은 모양이고, `onLoad` 와 달리 **컴포넌트가 다시 마운트될 때마다** 불려서 라우트
이동 후에도 지도가 되살아난다. `strategy` 는 기본값(`afterInteractive`)이다 — 지도는 첫 페인트에
필요하지 않고(리스트가 먼저 뜬다), `beforeInteractive` 는 루트 레이아웃에만 놓을 수 있는데 그
파일은 이번 task 소유가 아니다.

| 쓰는 API | 어디에 |
|---|---|
| `new kakao.maps.Map(container, { center, level, draggable, zoomable })` | 지도 생성 |
| `kakao.maps.event.addListener(map, "idle", …)` | 이동 종료 감지 |
| `map.getBounds()` → `getSouthWest()`·`getNorthEast()` → `getLat()`·`getLng()` | 영역 읽기 |
| `map.setBounds(new kakao.maps.LatLngBounds(sw, ne))` | 첫 진입에 매물이 다 보이게 맞추기 |
| `new kakao.maps.CustomOverlay({ position, content, clickable, xAnchor, yAnchor, zIndex })` | **가격 핀** |
| `map.setCenter(...)` · `map.relayout()` | 카드 선택 시 이동 · 스냅으로 높이가 바뀔 때 |

핀은 `Marker`(고정 이미지) 대신 **`CustomOverlay`** 다 — 가격 라벨을 얹어야 하기 때문이다.
`content` 로 `document.createElement("button")` 을 직접 넘기고 클래스는 panda 가 정적으로 뽑아 둔
`css({...})` 결과를 붙인다(React 밖에서도 스타일이 적용되고 **하드코딩 색상 0** 이다).

### 키가 없거나 도메인이 등록되지 않았을 때

JS 키는 **카카오 개발자센터에 등록한 도메인에서만** 동작한다. 그래서 `KakaoMap` 은 지도가 없어도
화면이 성립하도록 만들었다.

- 키(`NEXT_PUBLIC_KAKAO_MAP_JS_KEY`)가 없으면 스크립트를 아예 붙이지 않고 안내 면을 그린다.
- 로딩이 실패하면(`onError`) 같은 안내 면으로 떨어진다.
- **어느 경우에도 컨테이너와 `data-pin-count`·`data-map-status` 는 그대로 렌더된다.**
  리스트·필터·상세 이동은 지도 없이도 전부 동작한다.

### `GET /api/address/reverse` 는 쓰지 않았다

[T3.1 문서](./t3.1-listing-create.md#get-apiaddressreverselatlng)가 "T3.2(지도 핀 이동 → 주소
표시)가 쓸 자리" 라며 역지오코딩 프록시를 함께 열어 뒀는데, **이 화면에는 옮기는 핀이 없다.**
핀은 매물의 위치를 **보여 주는** 것이고 사용자가 지점을 고르는 화면이 아니다(주소를 고르는 곳은
건물 등록·근무지 등록이고 거기는 이미 `AddressSearchField` 를 쓴다). 억지로 부르면 지도를 움직일
때마다 외부 호출이 하나 더 늘어날 뿐이라 연결하지 않았다 — 라우트는 그대로 살아 있고
T3.5(통근 출발지 지정 등)나 뒤 task 가 필요할 때 그대로 쓰면 된다.

## 화면 — sticky 지도 + 스냅 시트

절대 위치 오버레이 대신 **`position: sticky` 지도 + 그 아래로 흐르는 시트**다. 480px 셸은
탭바가 있을 때와 없을 때 높이가 달라서(비로그인은 탭바가 없다) 화면 전체를 절대 좌표로 잡으면
두 경우 중 하나가 반드시 어긋난다. sticky 는 문서 흐름 그대로라 둘 다 자연스럽고, iOS 주소창이
접히며 `dvh` 가 변해도 깨지지 않는다.

스냅은 **지도 높이 3단**이다 — `peek`(60dvh) → `half`(42dvh, 기본) → `full`(0, 목록만).
시트 손잡이를 누르거나 위아래로 끌면 바뀌고(`data-snap` 으로 드러난다), 시트 머리는 지도 바로
아래에 sticky 로 붙어 손잡이가 늘 손에 닿는다. 배지는 `@zari/ui` `Badge` 의 `tone` 만 쓴다(T0.6).

필터·영역은 `history.replaceState` 로 **주소창에만** 반영한다 — 네비게이션을 일으키지 않아
지도가 다시 그려지지 않고, 새로고침·공유하면 서버 컴포넌트가 그 값으로 첫 화면을 그린다
(T4.1 커뮤니티 보드와 같은 방식).

## 통근 배지 — T3.5 가 붙을 자리

**[T3.5](./t3.5-commute.md) 가 소유한 계산은 하지 않았다.** 여기서 한 것은 배선과 화면뿐이다.

| 한다 | 하지 않는다 |
|---|---|
| `CommuteCache` 에 **이미 있는 행**을 읽는다 | 카카오모빌리티·ODsay 호출 |
| 그 근무지가 **내 것인지** 판정한다(`resolveCommuteWorkplace`) | `CommuteCache` upsert |
| 캐시가 없으면 `null` 을 준다 | 없다고 계산을 시작하는 것 |

- 화면: 시트 상단의 **「통근 기준」 셀렉트**(로그인 세입자 + 근무지 ≥ 1곳일 때만)에서 근무지를
  고르면 `?workplaceId=` 가 붙어 다시 조회되고, 카드에 `listing-commute-badge` 배지가 뜬다.
  캐시가 없으면 「통근시간 미조회」 배지로 **자리를 드러낸다**(비어 있는 것과 구분된다).
- **실패는 전부 조용히 무시한다.** 비로그인·세입자 아님·남의 근무지·없는 id 는 403 이 아니라
  `commuteWorkplaceId: null` 이다 — 공개 API 에서 403 을 주면 "그 id 의 근무지가 있다" 가 새어 나간다.

## robots — 색인을 연다

| 화면 | robots | 근거 |
|---|---|---|
| `/search` | **`index, follow`** + `canonical: /search` | 개인정보가 한 줄도 없고(등록자 이름조차 담지 않는다) 매물 탐색은 **검색 유입 자체가 목적**인 그로스 경로다 |

공개 고지서(T1.8)가 통째로 `noindex` 인 것과 정반대다 — 그쪽은 이름·호실·금액이 든 개인 문서이고
이쪽은 광고다. 환급 계산기(T2.3, `index`)와 같은 편에 선다.

필터·영역이 붙은 주소는 사실상 무한히 만들어질 수 있으므로 **canonical 을 `/search` 로 고정**해
색인이 한 곳으로 모이게 했다(중복 색인·크롤 예산 낭비 방지). 화면도 필터를 `replaceState` 로만
반영해 새 URL 을 히스토리에 쌓지 않는다. 값이 요청에 의존하지 않으므로 `generateMetadata` 함수가
아니라 **정적 `metadata` 객체**다(Next 문서가 그 경우 정적 객체를 쓰라고 못박는다 — T2.3 과 같은 판단).

### E2E 에서 지도 — 일부러 막는다

카카오 JS 키는 **등록한 도메인에서만** 동작한다(현재 `localhost:3000`·`localhost:3100`·
`127.0.0.1:3100`·`demo-zaritalk.vercel.app`). E2E 포트는 `E2E_PORT` 로 바뀌므로 그 목록에 없을 수
있고, 지도 타일은 외부 네트워크·쿼터에 매달린 리소스라 단언에 넣으면 여정 전체가 남의 사정에 흔들린다.

그래서 `page.route("**/dapi.kakao.com/**", abort)` 로 **SDK 요청 자체를 막고** 지도가 없는 상태로
여정을 지나간다. 검증은 ①**지도 컨테이너 존재**(`data-testid="search-map"`) ②**핀 데이터**
(`data-pin-count`) ③**리스트 카드**로 한다. 실제 타일·마커 렌더는 등록된 도메인(로컬 3000·배포)에서
눈으로 확인한다. 같은 이유로 T3.1 은 카카오 주소 검색을 프록시 앞에서 가로챈다(`e2e/address.ts`).

- **E2E① 매물 등록 → 비로그인 `/search` → 필터·영역 동기화 → 상세 진입**:
  임대인 로그인 → 성수·강남 좌표 건물·호실 생성(API) → **화면 폼으로 월세 매물 등록**(T3.1) →
  강남 전세 등록(API) → **비로그인 컨텍스트**로 `/search`(`/api/me` 401, 리다이렉트 없음) →
  두 매물 카드 · 서버가 만든 가격 문자열 → 영역으로 가둔 `?bounds=` 에서 **핀 2개·"2개 매물"** →
  전세 필터 → **1개**(핀도 1) → 성수만 담는 영역 → 강남 빠짐 → 스냅 손잡이(`data-snap`) →
  카드 클릭 → 공개 상세(가격·제목·상태·설명·통근 CTA·문의 더미·**OG·JSON-LD**) → 트래킹 3종
- **E2E② 없는 매물 404 · 종료 매물**: 없는 id → 404 · 공개 중일 때 탐색 노출 → `CLOSED` 전환 →
  **탐색에서 사라짐** · 상세는 열리되 배너 + **`noindex`**

호실을 스펙 안에서 직접 만드는 이유: 시드 101호는 앞선 스펙(`e2e/listing.spec.ts`)이 이미
건드리므로 상태를 빌리지 않는다(E2E 는 시드를 한 번만 돌리고 파일 순서대로 이어 달린다).
