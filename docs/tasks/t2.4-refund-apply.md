## 화면 흐름 — 왜 「임시저장」이 먼저인가

```
계산기(T2.3) ──CTA(계산 입력을 쿼리로)──▶ /tenant/refund/apply
                                          │
                          ① 내용 입력 ────┤ (계약 선택 시 월세·기간 자동 채움)
                          ② 임시저장 ─────┤ POST /api/refunds → DRAFT 생성
                          ③ 서류 업로드 ──┤ POST /api/uploads (applicationId 필요)
                          ④ 제출 ─────────┘ POST /api/refunds/[id]/submit
                                          ▼
                                    /tenant/refund (스테퍼)
```

업로드 엔드포인트가 `applicationId` 를 **요구한다** — 어디에도 매달리지 않은 파일이 스토어에 남는 것을 막고, 권한 판정("내 신청인가")을 업로드 **전에** 끝내기 위해서다. 그래서 서류를 붙이려면 신청이 먼저 있어야 하고, 화면이 그 순서를 눈에 보이게 안내한다(임시저장 전에는 업로더 대신 안내 문구).

- 신청서에 들어오면 **작성 중인 DRAFT 를 서버가 먼저 찾아** 이어서 쓴다(`getMyDraft`). 작성 중인 신청은 계정당 하나뿐이고, 이미 있는데 또 만들면 409 다.
- 계산기에서 넘어온 값이 유효하면 **화면에 들어오자마자** 미리보기를 돌린다 — 계산기가 보여 준 금액이 그대로 재현되는지 사용자가 바로 확인한다.
- 제출 버튼은 **필수 서류가 다 찰 때까지 비활성**이고, 서버가 같은 규칙으로 한 번 더 막는다.

## 서류 저장소 — Vercel Blob **private** (D3)

스토어 `zari-demo-docs` 는 **private** 이다. 계약서·주민등록등본이라 public 이면 URL 하나만 새어 나가도 남의 등본이 열린다.

| 항목 | 값 |
|---|---|
| 패키지 | `@vercel/blob@^2.8.0` (web 에만 설치 — 어드민은 web 을 거친다) |
| 쓰기 | `put(pathname, body, { access: "private", contentType, allowOverwrite: true })` |
| 읽기 | `get(pathname, { access: "private" })` → `{ statusCode, stream, blob }` 를 라우트가 스트리밍 |
| 경로 | `refunds/<applicationId>/<documentId>.<ext>` — 신청 단위로 묶인다 |
| 인증 | 로컬·CI 는 `BLOB_READ_WRITE_TOKEN`, Vercel 위에서는 OIDC(`BLOB_STORE_ID` + 자동 회전 토큰) |

### 읽기는 왜 서명 URL 이 아니라 프록시 라우트인가

`GET /api/refunds/[id]/documents/[documentId]` 가 **요청마다 권한을 확인하고** 스트림을 흘려보낸다.

- 이 서류를 볼 수 있는 사람은 "그 신청의 세입자 **또는** 어드민" 이라 **요청마다 판정이 다르다.** 한 번 발급된 서명 URL(`issueSignedToken` + `presignUrl`)은 유효시간 동안 **누구에게 전달돼도 열리므로** 이 판정을 표현할 수 없다.
- Vercel 문서도 private blob 은 미들웨어·CDN 캐시에 기대지 말고 **`get()` 바로 옆에서** 인증하라고 못박는다.
- 응답 헤더: `Cache-Control: private, no-store` · `X-Content-Type-Options: nosniff` · `Content-Disposition: inline; filename*=UTF-8''…`
- **DTO 에 Blob URL 을 싣지 않는다.** 화면에 내려가는 것은 `viewHref`(위 경로)뿐이다 — 단위 테스트가 응답 본문에 스토어 URL 이 없는지 확인한다.

### 드라이버 — 테스트·CI 는 네트워크를 타지 않는다

| 조건 | 드라이버 |
|---|---|
| `ZARI_UPLOAD_DRIVER=memory\|blob` | 그 값(마지막 수단) |
| `DATABASE_URL` 이 **테스트 DB**(이름에 `test`) | `memory` |
| `BLOB_READ_WRITE_TOKEN`·`BLOB_STORE_ID` 둘 다 없음 | `memory` |
| 그 밖(운영·프리뷰) | `blob` |

테스트 DB 판정을 기준으로 삼은 이유: E2E 는 `playwright.config.ts` 가 `DATABASE_URL` 만 테스트 DB 로 바꿔 web 을 띄우는데(그 파일은 이 task 소유가 아니라 손대지 않았다), **"테스트 DB 를 보고 있다" 가 곧 "지금은 테스트다"** 이기 때문이다. 운영 DB 를 보면서 memory 로 떨어질 길이 없다. 판정 규칙은 `@zari/db/testing` 의 `assertTestDatabase()` 와 같은 정규식이다.

### 업로드 제한과 근거

| 제한 | 값 | 왜 |
|---|---|---|
| 타입 | `application/pdf` · `image/jpeg` · `image/png` · `image/webp` | 계약서·등본은 스캔 PDF 아니면 휴대폰 사진이다. 그 밖(hwp·zip·exe)은 심사자가 열 수 없거나 위험하다 |
| 파일당 크기 | **4MB** | Vercel Functions 요청 본문 상한이 4.5MB 다. 서버 업로드는 파일이 함수를 통과하므로 그 아래로 잡았다. 더 커져야 하면 클라이언트 업로드(`handleUpload`)로 바꿔야 한다 |
| 슬롯당 | 5장 | 등본·계약서는 여러 장으로 스캔되곤 한다 |
| 신청당 | 12장 | 심사 화면이 감당할 양 |
| 파일명 | 200자 · 경로/제어문자 제거 | `../` 같은 경로 조작을 pathname 에 싣지 않는다 |

확장자와 MIME 을 **둘 다** 본다 — `File.type` 은 비어 오거나 `application/octet-stream` 일 수 있어서다. 둘이 어긋나면(`계약서.pdf` + `image/png`) 거부한다. 화면도 **같은 함수**로 먼저 걸러 4MB 파일을 헛되이 올리지 않는다.

## `documents` Json 에 무엇이 들어가나 — 스키마를 못 늘려서 한 선택

`RefundApplication` 에는 **월세·임차기간·기준일을 담을 컬럼이 없다**(있는 것은 `annualIncome`·`startYear`·`endYear`·`expectedAmount` 넷). 그런데 어드민 심사 화면은 "산출 내역"(연도별 개월·지급 월세·공제액)을 보여 줘야 하고, 그러려면 계산 입력 전부가 필요하다. 컬럼을 늘리려면 마이그레이션이 필요한데 **스키마는 Phase 5 가 잡고 있어 이 task 가 건드릴 수 없다.**

그래서 `documents`(`Json?`)를 **봉투(envelope)** 로 쓴다:

```jsonc
{
  "version": 1,
  "files": [                                  // 원래 용도 — 서류 메타 배열
    {
      "id": "9f2c…", "slot": "LEASE_CONTRACT", "name": "임대차계약서.pdf",
      "contentType": "application/pdf", "size": 182734,
      "pathname": "refunds/<applicationId>/9f2c….pdf",
      "url": "https://<store>.private.blob.vercel-storage.com/…",   // 서버에만 남는다
      "uploadedAt": "2026-09-02T04:11:20.512Z",
      "stage": "INITIAL"                      // INITIAL | SUPPLEMENT(보완요청 후 올림)
    }
  ],
  "calc": {                                   // 산출 내역 재현용
    "monthlyRent": 500000, "startDate": "2025-01-01",
    "endDate": "2025-12-31", "asOf": "2026-09-02"
  }
}
```

- **`asOf` 를 함께 굳히는 것이 핵심이다.** 소급 5년 창은 해가 바뀌면 밀리므로, 기준일을 저장하지 않으면 같은 신청이 내년에 다른 금액을 보여 준다. 저장해 두면 `expectedAmount` 와 재계산 결과가 언제 봐도 일치한다.
- 읽기는 **관대하게** 한다 — 봉투가 아니라 맨 배열이 들어 있어도 서류 목록으로 읽는다.
- **제대로 하려면 컬럼이 맞다**(`monthlyRent Int` · `startDate`/`endDate` · `asOf`, 또는 `calcSnapshot Json`). 스키마를 열 수 있게 되면 옮기고 봉투는 지운다 → [스키마가 필요했지만 만들지 않은 것](#스키마가-필요했지만-만들지-않은-것)

### `POST /api/refunds`

```jsonc
// 요청 — 계산 입력(T2.3 과 같은 4개) + (선택) 내 계약
{ "grossSalary": 48000000, "monthlyRent": 500000,
  "startDate": "2025-01-01", "endDate": "2025-12-31", "leaseId": "cmf0…" }

// 201 — 언제나 DRAFT. 금액은 서버가 calculateRefund 로 다시 계산해서 저장한다
{ "application": { "…위 DTO…", "status": "DRAFT", "expectedAmount": 1020000 } }
```

| 실패 | status · code |
|---|---|
| 비로그인 | 401 `UNAUTHORIZED` |
| 세입자 프로필 없음 | 403 `FORBIDDEN` |
| 금액 0원·음수·소수·문자, 날짜 형식, 기간 역전 | 400 `VALIDATION_ERROR` |
| 달력에 없는 날짜 | 400 `VALIDATION_ERROR` "존재하지 않는 날짜입니다." |
| **임차 시작일이 미래** | 400 `VALIDATION_ERROR` |
| `leaseId` 가 없는 계약 | 404 `NOT_FOUND` |
| `leaseId` 가 **내 계약이 아님** | 403 `FORBIDDEN` |
| **이미 작성 중인 DRAFT 가 있음** | 409 `CONFLICT` |

### `PATCH /api/refunds/[id]`

요청은 `POST` 와 같은 모양이다(부분 수정을 받지 않는다 — 네 값이 한 벌로 맞물려 계산되므로 절반짜리 입력으로 재계산하면 안 된다).

```jsonc
// 200 — 이미 올린 서류는 그대로 두고 계산 입력만 갈아 끼운다
{ "application": { "…DTO…" } }
```

| 실패 | status · code |
|---|---|
| 비로그인 401 · 세입자 프로필 없음 403 · 없는 신청 404 · 남의 신청 403 | 위와 같다 |
| **DRAFT 가 아닌 신청 수정** | **409 `CONFLICT`** — 제출한 뒤에는 내용이 굳는다(심사자가 본 숫자가 조용히 바뀌면 안 된다) |
| 값 검증 | `POST` 와 같다 |

### `POST /api/refunds/[id]/submit`

요청 본문 없음. 목표 상태는 상태 머신이 정한다 — `DRAFT → SUBMITTED`, `NEED_MORE_DOCS → REVIEWING`.

```jsonc
// 200
{ "application": { "…DTO…", "status": "SUBMITTED", "submittedAt": "2026-09-02T04:20:00.000Z" } }
```

| 실패 | status · code |
|---|---|
| **필수 서류 부족** | 400 `VALIDATION_ERROR` + `details.missingSlots: ["RESIDENT_REGISTRATION"]` |
| **보완요청 이후 추가한 서류가 없음** | 400 `VALIDATION_ERROR` |
| 제출할 수 없는 상태(이미 제출·심사중·종결) | 409 `CONFLICT` |
| 비로그인 401 · 없는 신청 404 · 남의 신청 403 | — |

- 최초 제출 시각(`submittedAt`)은 **한 번만** 찍는다 — 보완 재제출이 접수 시각을 밀어내면 심사 큐 정렬(오래 기다린 순)이 흔들린다.
- 저장은 전이 전 상태를 조건에 넣은 단일 `updateMany` 라 두 번 눌러도 한 번만 성공한다.

### `POST /api/uploads`

`multipart/form-data` — `file`(File) · `applicationId` · `slot`.

```jsonc
// 201
{
  "document": { "id": "9f2c…", "slot": "LEASE_CONTRACT", "slotLabel": "임대차계약서",
                "name": "임대차계약서.pdf", "contentType": "application/pdf", "size": 182734,
                "uploadedAt": "2026-09-02T04:11:20.512Z", "stage": "INITIAL",
                "viewHref": "/api/refunds/cmf0…/documents/9f2c…" },
  "application": { "…갱신된 DTO…" }
}
```

| 실패 | status · code |
|---|---|
| 비로그인 401 · 없는 신청 404 · 남의 신청 403 | — |
| multipart 아님 · 파일 없음 · 모르는 슬롯 | 400 `VALIDATION_ERROR` |
| **허용하지 않는 타입** | 400 `VALIDATION_ERROR` + `details.reason: "TYPE_NOT_ALLOWED"` |
| **4MB 초과** | 400 + `details.reason: "TOO_LARGE"` |
| 빈 파일 | 400 + `"EMPTY_FILE"` |
| 장수 초과 | 400 + `"TOO_MANY_FILES"` |
| 올릴 수 없는 상태(제출·심사중·종결) | 409 `CONFLICT` |

- `stage` 는 **업로드 시점의 상태**로 정한다 — `NEED_MORE_DOCS` 면 `SUPPLEMENT`, 아니면 `INITIAL`.

### `GET /api/refunds/[id]/documents/[documentId]`

서류 원본 스트리밍(private Blob). **낸 세입자 또는 어드민**만. 401 · 403 · 404(없는 신청·없는 서류·스토어에 파일 없음).
