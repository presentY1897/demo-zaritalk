# T3.4 근무지 관리

> Phase 3 · 상태: ✅ · [Phase 구성](../PHASES.md)

| 라우트/API | 동작 |
|---|---|
| `/tenant/workplaces` | 라벨+주소 검색(좌표), 복수 등록 |
| `GET·POST /api/workplaces` | 내 근무지 목록·등록 |
| `PATCH·DELETE /api/workplaces/[id]` | 수정·삭제 |

> 표의 "CRUD" 를 채우면서 수정·삭제를 `/[id]` 로 나눴다(나머지 리소스와 같은 모양).

**[T3.1 매물 등록](./t3.1-listing-create.md)과 한 묶음으로 작업했다** — 둘 다 주소 검색이
필요해서 공용 컴포넌트를 T3.1 문서에 정리해 뒀다(컴포넌트 API·프록시 스펙·교체한 수동 입력 3곳).

## 권한 — 본인 프로필 것만

| 상황 | status · code |
|---|---|
| 비로그인·만료 세션 | 401 `UNAUTHORIZED` |
| 세입자 프로필 없음(임대인 계정 등) | 403 `FORBIDDEN` |
| 없는 근무지 id | 404 `NOT_FOUND` |
| **남의 근무지** | 403 `FORBIDDEN` |

- **목록은 세입자 프로필 id 로 걸러 조회**한다 — 남의 근무지가 섞일 구조 자체가 아니다.
- **등록은 로그인한 계정의 세입자 프로필에 붙인다** — 요청 본문으로 프로필을 지정할 수 없다.
- 세입자 프로필은 활성 프로필 쿠키가 아니라 **유형으로** 고른다(T1.3 `findTenantProfile`).
- 남의 자원을 404 로 감추지 않고 403 을 주는 것은 T1.1·T1.3 과 같은 선택이다.

## 좌표 범위 검증

`features/address/coords.ts` 가 **단일 출처**다 — 위도 33~39 / 경도 124~132(대한민국).

- 화면에는 위경도 입력칸이 **없다.** 좌표는 주소 검색으로 고른 후보에서만 들어온다.
- 그래도 **서버 스키마에서 막는다** — API 를 직접 부를 수 있기 때문이다.
  숫자가 아니어도(문자열) 400 이다(`z.number()` 라 강제 변환하지 않는다).
- 수정할 때 **주소만 보내면 400** 이다. 주소와 좌표가 어긋나면 T3.5 통근시간이 엉뚱한 지점으로
  계산되므로 `address`·`lat`·`lng` 를 함께 받는다.

## 그 밖의 규칙

| 규칙 | 이유 |
|---|---|
| 한 세입자당 **5곳**(`WORKPLACE_MAX`) — 넘으면 409 | T3.5 가 `(호실, 근무지)` 쌍마다 외부 API 를 부른다. 쌍이 무한정 늘지 않게 |
| 같은 이름의 근무지 중복 금지 — 409 | 목록에서 구별이 안 된다. 스키마에 unique 제약이 없어(다른 세입자와는 겹쳐도 된다) 라우트에서 본다 |
| 삭제하면 `CommuteCache` 도 사라진다 | 스키마의 `onDelete: Cascade` |

## 요청·응답

에러는 D1 규약대로 `{ "error": { "code", "message", "details?" } }` 한 형태다.

### `GET /api/workplaces`

```jsonc
// 200 — 내 것만. 먼저 등록한 것부터
{
  "workplaces": [
    { "id": "cmf0…", "label": "회사", "address": "서울 강남구 강남대로 396",
      "lat": 37.49794, "lng": 127.02762, "createdAt": "2026-09-01T00:00:00.000Z" }
  ]
}
```

### `POST /api/workplaces`

```jsonc
// 요청 — 좌표는 주소 검색(`GET /api/address/search`)에서 고른 값이다
{ "label": "회사", "address": "서울 강남구 강남대로 396", "lat": 37.49794, "lng": 127.02762 }
// 201 { "workplace": { …WorkplaceDto… } }
```

| 실패 | status · code |
|---|---|
| 비로그인 | 401 `UNAUTHORIZED` |
| 세입자 프로필 없음 | 403 `FORBIDDEN` |
| 라벨 빈 값·20자 초과, 주소 2자 미만, **좌표 범위 밖·숫자 아님** | 400 `VALIDATION_ERROR` |
| 같은 이름 중복 · 5곳 초과 | 409 `CONFLICT` |

### `PATCH /api/workplaces/[id]` · `DELETE /api/workplaces/[id]`

```jsonc
// 요청 — 보낸 필드만 바뀐다. 주소를 바꾸려면 좌표를 함께 보낸다
{ "label": "본가" }
{ "address": "서울 성동구 왕십리로 300", "lat": 37.56133, "lng": 127.03782 }
// 200 { "workplace": { …WorkplaceDto… } }
```

빈 본문 `{}` 은 400. 삭제는 `204 No Content`.

## 화면

- 진입점은 **세입자 홈의 「근무지 관리」 카드**(`data-testid="tenant-workplace-link"`)다.
  세입자 탭바(T0.5)는 홈·매물·환급·커뮤니티·마이 5칸이 확정돼 있어 자리가 없다 —
  탭 구성을 건드리지 않고 홈에 카드 하나를 더했다.
- 목록 카드마다 「통근 기준점」 배지 + 주소 + 좌표를 보여 준다. 추가·수정·삭제는 시트에서 한다.
- **장소 검색 결과를 고르면 라벨이 비어 있을 때 장소명으로 채워 준다**
  ("왕십리역" 검색 → 라벨 "왕십리역"). `AddressSelection.placeName` 을 쓰는 유일한 곳이다.
- `Workplace` 에는 `roadAddress` 컬럼이 없어 **표시용 한 줄**(`displayAddress` = 도로명 ?? 지번)을
  `address` 에 저장한다. 시드(`서울 강남구 강남대로 396 (강남역)`)와 같은 결이다.

> 스키마(`packages/db/prisma/**`)는 이번 task 소유가 아니라 손대지 않았다. `Workplace` 에
> `@@unique([tenantProfileId, label])` 와 `roadAddress` 컬럼이 있으면 더 깔끔한 지점이 있다 —
> [T3.1 문서의 "스키마를 건드리지 않고 앱에서 막은 것"](./t3.1-listing-create.md#스키마를-건드리지-않고-앱에서-막은-것) 참고.

## T3.5(통근시간)가 쓸 것

| 무엇 | 어디 |
|---|---|
| 기준점 목록(서버) | `features/workplace/queries.ts` 의 **`listWorkplaces(tenantProfileId)`** — 라우트와 페이지가 쓰는 바로 그 함수 |
| 기준점 목록(클라이언트) | `GET /api/workplaces` 또는 `useWorkplaces()` / 캐시 키 `workplaceKeys.list` |
| 좌표 | `WorkplaceDto.lat` · `lng` — 이미 대한민국 범위가 보장된다 |
| 소유권 판정 | `requireOwnWorkplace(tenant, workplaceId)` — `POST /api/commute` 가 "내 근무지인가" 를 물을 때 그대로 쓴다 |
| 캐시 정리 | 근무지 삭제 시 `CommuteCache` 는 cascade 로 함께 사라진다 — T3.5 가 따로 지울 필요가 없다 |

`(호실, 근무지)` 쌍의 호실 쪽은 T1.1 의 `Unit`·`Building`(lat/lng)이다.
