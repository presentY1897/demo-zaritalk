## ① 위젯 SDK 호출 시퀀스 (`@tosspayments/tosspayments-sdk` v2.8.1)

받은 키가 `test_gck_`/`test_gsk_` 라 **주문서형(결제위젯)** 이다. 구버전 결제창 SDK(`ck`/`sk`)가 아니다.

```ts
import { loadTossPayments, type TossPaymentsWidgets } from "@tosspayments/tosspayments-sdk";

// ── 마운트 시 (한 번만)
const tossPayments = await loadTossPayments(clientKey);          // NEXT_PUBLIC_TOSS_CLIENT_KEY
const widgets = tossPayments.widgets({ customerKey });           // 세입자 프로필 cuid (비회원이면 ANONYMOUS)
await widgets.setAmount({ currency: "KRW", value: amount });     // ★ 렌더 전에 반드시
await Promise.all([
  widgets.renderPaymentMethods({ selector: "#toss-payment-method" }),
  widgets.renderAgreement({ selector: "#toss-payment-agreement" }),
]);

// ── 결제 버튼 클릭 시
const checkout = await createCheckout(charge.id);                // 서버가 orderId·금액 확정
await widgets.requestPayment({
  orderId: checkout.orderId,                                     // 영문·숫자·`-`·`_`·`=` 6~64자
  orderName: checkout.orderName,                                 // 최대 100자
  successUrl: `${window.location.origin}/tenant/pay/success`,    // 오리진 포함 절대 URL
  failUrl: `${window.location.origin}/tenant/pay/fail`,
  customerName: checkout.customerName,
});
// Redirect 방식이라 반환값은 void 다 — 브라우저가 이동한다
```

리다이렉트 쿼리(SDK v2 문서 그대로):

```
{successUrl}?paymentType={NORMAL|BRANDPAY}&amount={AMOUNT}&orderId={ORDER_ID}&paymentKey={PAYMENT_KEY}
{failUrl}?code={ERROR_CODE}&message={ERROR_MESSAGE}&orderId={ORDER_ID}
```

**빠뜨리면 터지는 것들** (SDK 타입 정의에 명시된 에러):

| 실수 | 에러 |
|---|---|
| `setAmount` 없이 렌더 | `NotSetupAmountError` |
| 위젯을 두 번 렌더 | `PaymentMethodsWidgetAlreadyRenderedError` |
| `successUrl` 이 상대경로 | `IncorrectSuccessUrlFormatError` |
| 필수 약관 미동의 상태로 결제 요청 | `NeedAgreementWithRequiredTermsError` |

> **React StrictMode 함정 — 실제로 밟았다.** 개발 모드는 effect 를 두 번 돌린다.
> `startedRef` 로 두 번째 실행을 막는 것만으로는 부족하고, **cleanup 에서 취소 플래그를 세우면
> 안 된다.** 첫 실행의 promise 가 "취소됨" 으로 버려져 위젯 iframe 은 그려졌는데 결제 버튼이
> 영원히 비활성으로 남는다. E2E 프로브로 잡아 고쳤다(`e2e/pay.spec.ts` 가 버튼 활성까지 본다).

## ② 금액이 화면에서 조작되지 않게

- 화면이 보여 주는 금액은 **서버가 계산해 준 `charge.outstanding`**(원장 엔진 `calcOutstanding`)이다.
- 실제 결제 금액은 **결제 버튼을 누르는 순간 `POST /api/toss/checkout` 이 다시 확정**한다.
- 둘이 다르면(그 사이 임대인이 수기 납부를 기록한 경우) **결제를 진행하지 않고** 새로고침을 안내한다.
- 승인 검증은 서버가 3중으로 한 번 더 한다([T2.1 ②](./t2.1-toss-api.md#-금액-위변조-검증--3중)).

## ③ 화면별 동작

| 화면 | 핵심 |
|---|---|
| `/tenant/pay/[chargeId]` | 청구 내역(0원 줄 숨김) + 이미 납부액 차감 표시 + 위젯 + 「{금액} 결제하기」. 잔액 0이면 위젯 대신 `pay-settled` 안내. 내 청구가 아니면 **404 화면**(API 는 404/403 을 구분한다) |
| `/tenant/pay/success` | 마운트 시 `POST /api/toss/confirm` **한 번만** 호출 → 영수증(결제수단·주문번호·토스 영수증 링크) + **원장 반영 확인**(청구 금액·납부 합계·남은 금액·상태 배지). 실패하면 사유 + 「다시 결제하기」(orderId → 청구 id 를 서버가 찾아 준다) |
| `/tenant/pay/fail` | 토스 에러 코드를 한글 문구로 바꿔 보여 준다(`PAY_PROCESS_CANCELED`·`REJECT_CARD_COMPANY` 등). **DB 를 건드리지 않는다** — GET 이고, 사용자가 창을 닫은 것일 수도 있다 |
| `/tenant/payments` | 합계(전체·자리페이) + 납부 목록. 수단 배지로 카드/기타 구분, 카드는 토스 영수증 링크 |

## ⑤ 세입자 홈 「자리페이로 결제」 연결 — **머지 담당자가 할 일**

버튼은 `features/tenant/**`(T1.3 소유, T2.6 과 동시 작업 중)에 있어 **이 task 에서 건드리지 않았다.**
연결은 아래 한 곳에서 `disabled` 를 떼고 링크로 감싸면 끝난다.

- **파일**: `apps/web/src/features/tenant/TenantHomeView.tsx`
- **컴포넌트**: `LeaseCard` (파일 내부. `data-testid="tenant-pay-cta"` 가 붙은 `<Button>`)
- **현재 코드**

```tsx
{/* T2.2(자리페이·토스) 자리 — 목적지 `/tenant/pay/[chargeId]` 가 아직 없어 비활성으로 둔다 */}
<div className={actionStyle}>
  <Button fullWidth disabled data-testid="tenant-pay-cta">
    자리페이로 결제{payable ? ` · ${formatKrw(currentCharge.outstanding)}` : ""}
  </Button>
  <p className={soonStyle}>카드 결제는 곧 제공됩니다 (T2.2).</p>
</div>
```

- **바꿀 코드** (`payable = currentCharge !== null && currentCharge.outstanding > 0` 는 이미 위에 있다)

```tsx
<div className={actionStyle}>
  {payable ? (
    <Link href={`/tenant/pay/${currentCharge.id}`}>
      <Button fullWidth data-testid="tenant-pay-cta">
        자리페이로 결제 · {formatKrw(currentCharge.outstanding)}
      </Button>
    </Link>
  ) : (
    <Button fullWidth disabled data-testid="tenant-pay-cta">
      자리페이로 결제
    </Button>
  )}
  <Link href="/tenant/payments" className={soonStyle}>
    납부 내역 보기
  </Link>
</div>
```

- **필요한 props**: 없다. `LeaseCard` 가 이미 받는 `card.currentCharge`(`ChargeDto`)의 `id` 와
  `outstanding` 만 쓴다. `Link` 는 이 파일에 이미 import 되어 있다.
- **추가로**: 같은 파일 상단 주석의 "Phase 2 가 채울 자리" 표에서 「자리페이로 결제」·「납부 이력」
  행의 *지금* 칸을 갱신하면 좋다.
- **E2E 영향 — 반드시 함께 고쳐야 한다**: `e2e/tenant.spec.ts:139` 가
  `await expect(page.getByTestId("tenant-pay-cta")).toBeDisabled();` 로 **비활성을 단언**한다.
  버튼을 연결하면 이 줄이 깨지므로, 활성 + `/tenant/pay/…` 링크를 확인하는 단언으로 바꿔야 한다
  (예: `await expect(page.getByTestId("tenant-pay-cta")).toBeEnabled();` +
  클릭 후 `await expect(page).toHaveURL(/\/tenant\/pay\//)`).
  `e2e/*` 기존 파일은 이 task 소유가 아니라 손대지 않았다.

세입자 탭바(`features/shell/tabs.ts`)에는 결제 탭을 추가하지 않았다 — T0.5 소유이고,
결제 진입점은 홈의 CTA 하나로 충분하다.

**통합(E2E)** — `e2e/pay.spec.ts` 4개:

| | 내용 |
|---|---|
| E2E① | 세입자 로그인 → 결제 화면 → 청구 내역·**잔액 700,000원** → **토스 위젯 iframe 2개(결제수단·약관) 실제 렌더** → 결제 버튼 활성 → `pay_checkout_view` 적재 |
| E2E② | `checkout` 금액을 서버가 정한다(요청에 `amount:1` 을 실어도 700,000) · **금액 위변조 confirm 400** · 없는 주문 404 · 비로그인 401 · 원장 무변경 |
| E2E②-b | 실패 콜백 화면 — 코드 한글화 + 「다시 결제하기」가 같은 청구로 돌아감 · 성공 콜백에 값이 없으면 승인하지 않음 |
| E2E③ | 카드 납부가 **세입자 납부 이력(「자리페이」 배지 + 영수증 링크)** 과 **임대인 수납 시트**에 함께 보인다 + 완납 청구는 결제 화면에서 `pay-settled` |

> **왜 위젯 결제를 끝까지 자동화하지 않았나** — 결제위젯은 카드사 인증 iframe 안에서 사람이 직접
> 입력해야 유효한 `paymentKey` 가 나온다. 그 iframe 을 스크립트로 통과시키면 토스 UI 가 바뀔 때마다
> 깨지는 불안정한 테스트가 된다. task 지침대로 **결제 직전까지는 브라우저로**(위젯 렌더·금액·버튼 활성),
> **승인 이후는 API·단위 테스트로** 나눠 검증했다.
> E2E① 은 `js.tosspayments.com` 스크립트를 받아 오므로 **네트워크가 필요하다.**

> E2E 는 시드 9월 청구(700,000원)를 쓰고 `test.afterAll` 에서 시드 상태로 되돌린다 —
> 뒤따라 도는 `tenant.spec.ts` 가 같은 청구를 「예정」으로 기대하기 때문이다(파일명 순서 직렬 실행).

## 후속 task 가 알아야 할 것

- **결제 취소 화면은 없다.** 세입자가 카드 결제를 스스로 취소하는 UI 도, 토스 취소 API 호출도
  만들지 않았다(T2.1 범위 밖). 웹훅으로 들어오는 취소만 원장에 반영된다.
- `/tenant/payments` 는 **탭바에 없다.** 홈 CTA 아래 링크(위 ⑤)와 결제 성공·실패 화면에서 들어간다.
- 환급(T2.4)이 납부 이력을 쓰고 싶으면 `features/pay/queries.ts` 의 `listTenantPayments` 를 그대로 쓰면 된다.
- **[PHASES.md](../PHASES.md) 의 T2.2 상태(⬜)는 갱신하지 않았다** — Phase 2 통합 시점에 함께 ✅ 로 바꾼다.
