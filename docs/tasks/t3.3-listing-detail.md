## 공개 라우트 위치 — `(app)/listings/[id]`

로그인 강제는 `(app)/(protected)/layout.tsx` 한 곳이 한다(T0.5). 그 그룹 **밖**에 두면 480px
셸은 그대로 쓰면서 로그인은 걸리지 않는다 — 공개 고지서(T1.8)·환급 계산기(T2.3)·`/search`(T3.2)와

## 서버 렌더 — 크롤러와 링크 미리보기가 JS 없이 읽는다

이 화면은 **검색 유입과 링크 공유의 착지점**이다. 크롤러와 카카오톡 미리보기 봇은 JS 를 돌리지
않으므로 조건·주소·사진이 HTML 안에 이미 있어야 하고, `generateMetadata` 는 서버 컴포넌트에서만
쓸 수 있다(T1.8 과 같은 판단). 그래서 본체는 서버 컴포넌트이고 **상호작용 세 조각만** 클라이언트다.

| 조각 | 하는 일 |
|---|---|
| `ListingDetailTracker` | 노출 1회 `listing_detail_view` |
| `ListingInquiryButton` | 문의 시트(더미) |
| `ListingCommuteButton` | 「내 근무지까지」(T3.5 자리) |

사진 갤러리는 **CSS scroll-snap** 이라 JS 가 없다. 위치 지도는 클라이언트지만 없어도 화면이
성립한다(주소는 지도 밖에 따로 적는다).

## `GET /api/listings/[id]` — T3.1 의 `GET` 을 **공개로 넓혔다**

T3.1 때 이 `GET` 은 소유 임대인·수락 중개인만 읽을 수 있었다(401·403). `/listings/[id]` 가 공개
상세 화면이 되면서 같은 리소스를 공개로 넓혔다. `PATCH`·`DELETE` 의 권한은 **그대로다**.

```jsonc
// 200 — 세션을 요구하지 않는다. `?workplaceId=` 는 통근 배지에만 쓴다
{
  "listing": {
    "id": "cmf0…", "unitId": "cmf0…",
    "dealType": "WOLSE", "deposit": 10000000, "monthlyRent": 500000, "status": "OPEN",
    "priceLabel": "월세 1,000만/50만", "pinLabel": "월 50만",
    "description": "역까지 도보 5분", "photos": ["https://cdn.example.com/a.jpg"],
    "availableFrom": "2026-11-01",
    "createdAt": "2026-09-02T…", "updatedAt": "2026-09-02T…",
    "listedBy": { "role": "LANDLORD" },          // 이름·연락처는 담지 않는다
    "unit": { "id": "cmf0…", "label": "101호", "floor": 1, "areaM2": 23.1, "rooms": 1 },
    "building": { "id": "cmf0…", "name": "행당해피빌", "address": "서울 성동구 행당동 347",
                  "roadAddress": "서울 성동구 행당로 79", "lat": 37.56152, "lng": 127.03648 },
    "commute": null                               // T3.5 자리 — 캐시 히트일 때만
  }
}
```

| 실패 | status · code |
|---|---|
| 없는 매물 id | 404 `NOT_FOUND` |
| `workplaceId` 형식 오류(빈 값·64자 초과) | 400 `VALIDATION_ERROR` |

### 공개 화면이 담는 것 / 담지 않는 것

| 담는다 | 담지 않는다 | 이유 |
|---|---|---|
| 건물 이름·주소·좌표, 호실 라벨·층·면적·방 수 | — | 매물을 고르는 데 필요한 정보다 |
| 등록자 **역할**(임대인 직접 / 중개인 등록) | 등록자 **이름**·연락처 | **이 페이지는 색인 대상이다.** 개인 이름이 검색 결과에 남으면 안 된다 |
| 상태(`OPEN`·`RESERVED`·`CLOSED`) | 계약·세입자·청구 어느 것도 | 매물과 무관하다 |

T3.1 의 `ListingDto`(등록자 이름 포함)를 그대로 쓰지 않고 **`PublicListingDto` 를 따로 둔 이유**가
이것이다 — `ListingDto` 는 임대인 **관리 화면**용이다. 테스트가 응답 문자열에 "김임대" 가 없음을 못 박는다.

### 예약·종료 매물도 404 로 감추지 않는다

링크(카카오톡 공유·북마크)가 이미 돌아다니는데 갑자기 404 가 되면 "잘못 눌렀나" 가 되고,
검색엔진에는 **소프트 404** 가 쌓인다. 대신

- 화면이 **상태 배너**를 띄운다("예약된 매물입니다" / "종료된 매물입니다").
- 메타가 **`noindex`** 로 내려간다(아래 robots 절).
- `/search` 목록에서는 **사라진다**(OPEN 만 노출).

### T3.1 테스트에서 고친 줄

`GET` 이 공개가 되면서 `app/api/listings/[id]/route.test.ts` 의 두 테스트가 필연적으로 깨졌다.
**그 두 개만** 다시 적고 나머지(PATCH·DELETE·상태 전이·권한)는 손대지 않았다.

| 전 (T3.1) | 후 (T3.3) |
|---|---|
| `"비로그인이면 401, 없는 매물이면 404"` | `"비로그인도 매물 상세를 읽는다 — 등록자 이름은 담기지 않는다"` + `"없는 매물이면 404"` |
| `"남의 매물이면 403"`(GET) | `"남의 매물도 상세는 읽히지만 수정·삭제는 403"` — **쓰기 권한은 그대로 검증한다** |
| `"소유 임대인은 매물 상세를 읽는다"` | 그대로 두되 위 테스트가 같은 단언을 포함해 흡수 |

## robots — 공개 중(OPEN)만 색인한다

| 상태 | robots | 근거 |
|---|---|---|
| `OPEN` | **`index, follow`** | 개인정보가 없고(등록자 이름조차 담지 않는다) 검색 유입이 목적인 페이지다 |
| `RESERVED` · `CLOSED` | **`noindex, follow`** | 더 이상 구할 수 없는 매물이다. 색인에 남으면 검색 결과가 거짓말이 된다(빈 상세로 들어온 사람이 이탈한다) |
| 없는 id | `noindex, nofollow` | 404 |

- `canonical: /listings/<id>` 를 항상 붙인다.
- `follow` 는 종료 매물에도 남긴다 — 그 페이지의 「매물 찾기로」 링크를 타고 살아 있는 목록으로
  가는 편이 낫다(`noindex, follow` 는 "이 페이지는 빼되 링크는 따라가라" 라는 뜻이다).
- 공개 고지서(T1.8)가 통째로 `noindex` 인 것과 다르다 — 그쪽은 이름·호실·금액이 든 **개인 문서**이고
  이쪽은 **광고**다. 환급 계산기(T2.3, `index`)·`/search`(T3.2, `index`)와 같은 편에 선다.

## 메타·OG

`generateMetadata`(Next 16 — `params` 는 Promise)에서 채운다. 매물마다 값이 달라지므로 정적
`metadata` 객체가 아니라 함수다(T1.8 과 같은 이유, T2.3·T3.2 는 반대 경우).

| 항목 | 값 |
|---|---|
| `title` | `행당해피빌 101호 월세 1,000만/50만 · 자리 데모` |
| `description` | `월세 1,000만/50만 · 원룸 · 23.1㎡ (약 7.0평) · 1층 · 서울 성동구 행당로 79 — 역까지 도보 5분` |
| `alternates.canonical` | `/listings/<id>` |
| `robots` | 위 표 |
| `openGraph` | `type: website` · `siteName` · `locale: ko_KR` · `url` · 같은 title·description · **첫 사진** |
| `twitter` | 사진이 있으면 `summary_large_image`, 없으면 `summary` |
| `metadataBase` | `NEXT_PUBLIC_WEB_URL`(없으면 localhost) |

- `og:type` 은 `website` 다. 매물은 글(`article`)이 아니고, schema.org 의 `product` 에 해당하는
  OG 타입은 Next 의 `OpenGraphType` 유니온에 없다.
- 제목·설명 문자열은 **JSON-LD 와 같은 함수**(`listingTitle`·`listingDescription`)에서 나온다 —
  검색 결과 제목과 구조화 데이터가 어긋나지 않는다.
- OG 이미지는 매물 사진이 있으면 그것을 쓰고, 없으면 넣지 않는다(T6.4 가 `opengraph-image` 를 붙일 자리).
- 없는 매물이면 메타도 "매물을 찾을 수 없습니다" + `noindex, nofollow` 로 내려간다.

## JSON-LD — `RealEstateListing` → `Offer` → `Apartment`

### 타입을 고른 근거

schema.org 가 **부동산 매물 페이지를 위해 만든 타입**이 `RealEstateListing` 이다("A
RealEstateListing is a listing that describes one or more real-estate Offers"). `WebPage` 의
하위 타입이라 "이 **페이지**가 매물 광고다" 를 말하고, 실제 거래 조건은 `mainEntity` 로 매단
`Offer` 가 말한다.

| 후보 | 버린 이유 |
|---|---|
| `Product` + `Offer` | 임대차는 물건 판매가 아니다. 보증금이 "판매가" 로 읽힌다 |
| `Apartment` 단독 | `Accommodation`(→`Place`)에는 **`offers` 속성이 없다**. 금액을 붙일 자리가 없다 |
| `Residence`·`House` | 데모 데이터가 다세대·원룸 호실이라 `Apartment` 가 더 가깝다 |
| `Offer` 를 최상위로 | 페이지가 곧 매물 광고라는 사실이 사라진다 |

`Offer` 에는 `Place` 를 매달 수 없고 `Place` 에는 금액을 매달 수 없으므로, 둘을 잇는 **유일하게
올바른 방향이 `Offer.itemOffered`** 다. 그래서 3단이 된다.

### 전세·월세를 금액으로 옮기기

한국식 보증금/월세에 대응하는 schema.org 타입은 없다. `Offer` 하나에 값 하나만 담을 수 있으므로:

- `price` — **정기적으로 내는 돈**. 월세면 `monthlyRent`, 전세면 `deposit`(한 번에 내는 전부)
- `priceSpecification[]` — 조건 **전부**를 이름 붙여 담는다
  - 보증금: `PriceSpecification` `{ name: "보증금" }`
  - 월세: `UnitPriceSpecification` `{ name: "월세", unitCode: "MON" }` — `MON` 은 UN/CEFACT 의 "월"
- `businessFunction: http://purl.org/goodrelations/v1#LeaseOut` — **파는 게 아니라 빌려주는 것**임을
  못 박는다. 이게 없으면 `price` 가 매매가로 읽힌다
- `availabilityStarts` — 입주가능일(없으면 키를 넣지 않는다)

```jsonc
{
  "@context": "https://schema.org",
  "@type": "RealEstateListing",
  "@id": "https://…/listings/cmf0…#listing",
  "url": "https://…/listings/cmf0…",
  "name": "행당해피빌 101호 월세 1,000만/50만",
  "description": "월세 1,000만/50만 · 원룸 · 23.1㎡ (약 7.0평) · 1층 · 서울 성동구 행당로 79 — 역까지 도보 5분",
  "datePosted": "2026-09-02T…", "inLanguage": "ko-KR",
  "image": ["https://cdn.example.com/a.jpg"],
  "mainEntity": {
    "@type": "Offer", "@id": "https://…/listings/cmf0…#offer",
    "name": "월세 1,000만/50만",
    "price": 500000, "priceCurrency": "KRW",
    "businessFunction": "http://purl.org/goodrelations/v1#LeaseOut",
    "availability": "https://schema.org/InStock",
    "availabilityStarts": "2026-11-01",
    "priceSpecification": [
      { "@type": "PriceSpecification", "name": "보증금", "price": 10000000,
        "priceCurrency": "KRW", "valueAddedTaxIncluded": true },
      { "@type": "UnitPriceSpecification", "name": "월세", "price": 500000,
        "priceCurrency": "KRW", "unitCode": "MON", "valueAddedTaxIncluded": true }
    ],
    "itemOffered": {
      "@type": "Apartment", "name": "행당해피빌 101호",
      "address": { "@type": "PostalAddress", "addressCountry": "KR",
                   "streetAddress": "서울 성동구 행당로 79" },
      "geo": { "@type": "GeoCoordinates", "latitude": 37.56152, "longitude": 127.03648 },
      "floorSize": { "@type": "QuantitativeValue", "value": 23.1, "unitCode": "MTK" },
      "numberOfRooms": 1, "floorLevel": "1"
    }
  }
}
```

| `ListingStatus` | `availability` |
|---|---|
| `OPEN` | `https://schema.org/InStock` |
| `RESERVED` | `https://schema.org/LimitedAvailability` |
| `CLOSED` | `https://schema.org/SoldOut` |

- 종료 매물도 JSON-LD 를 그대로 내보낸다 — 페이지가 살아 있으니 구조화 데이터가 그 상태를 정확히
  말해 주는 편이 낫다. 색인은 메타의 `noindex` 가 막는다.
- **모르는 값은 키 자체를 넣지 않는다**(면적·방 수·층·사진). `"floorSize": null` 은 "0" 으로 읽힐 수 있다.
- **`seller`·`author` 를 넣지 않는다** — 등록자 이름은 DTO 에 아예 없고 구조화 데이터에도 넣지 않는다.

### 직렬화 — `</script>` 를 막는다

`JSON.stringify` 만으로는 부족하다. 설명에 `</script>` 가 들어 있으면 스크립트 블록이 거기서
끊기고 그 뒤가 **HTML 로 해석된다**(XSS). `serializeJsonLd` 가 `<`·`>`·`&` 를 유니코드
이스케이프(`\u003c`·`\u003e`·`\u0026`)로 바꾼다 — JSON 의미는 그대로면서 HTML 파서가 태그로 읽지 못한다.
U+2028·U+2029 도 함께 막는다(JSON 에서는 유효하지만 JS 문자열에서는 줄바꿈이다).
테스트가 `</script><img onerror=…>` 를 넣어 이 경로를 못 박는다.

## 「내 근무지까지」 — T3.5 가 붙을 자리

**계산은 하지 않는다.** 지금 하는 일은 세 갈래뿐이다.

| 상태 (`data-commute-state`) | 버튼이 하는 일 |
|---|---|
| `anonymous`(비로그인) | `/login?from=listing&listing=<id>` — 통근시간을 보려면 근무지가 필요하고 근무지는 계정에 붙는다 |
| `no-workplace`(로그인·근무지 0곳) | `/tenant/workplaces`([T3.4](./t3.4-workplace.md) 화면) |
| `ready`(로그인·근무지 있음) | 시트를 열어 **근무지별 캐시된 값**을 보여 준다. 없으면 「아직 조회 전」 |

- 캐시는 `features/listing/commute.ts` 의 `readUnitCommutes(unitId, workplaces)` 가 읽는다 —
  **외부 API 를 부르지 않는다.**
- **T3.5 가 할 일**: `POST /api/commute` 로 `CommuteCache` 를 채우고, 시트의 「아직 조회 전」 배지
  자리를 「조회하기」 버튼으로 바꾼다. 결과는 같은 `ListingCommuteDto` 모양으로 이 컴포넌트에
  그대로 들어오므로 **표시 코드는 바뀌지 않는다.** 넘겨받을 것의 전체 목록은
  [T3.2 문서의 "T3.5 가 넘겨받을 것"](./t3.2-map-search.md#t35-가-넘겨받을-것) 참고.

## 문의는 더미다

실제 메시지·전화는 나가지 않는다. 진짜 문의 채널을 붙이려면 임대인·중개인 연락처를 공개 화면에
실어야 하는데 그건 개인정보이고 이 페이지는 색인 대상이다. 데모에서는 "문의가 어떻게 생겼는가"
까지만 보여 주고("앱 내 메시지(준비 중)"), 실제 연결은 T3.6(중개 요청)·T3.7(중개인 수신함) 쪽
채널로 넘긴다. 시트 안에 **"문의는 실제로 전송되지 않고 연락처도 공개되지 않습니다"** 를 명시한다.
