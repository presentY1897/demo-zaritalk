# T5.1 작업 의뢰 생성·민원 전환

> Phase 5 · 상태: ⬜ · [Phase 구성](../PHASES.md)

| 라우트/API | 동작 |
|---|---|
| `/landlord/workorders` | 의뢰 목록 — 직접 생성(업종·건물/호실·내용·희망일) 또는 민원 전환분. 상태: 요청→견적도착→배정→완료 |
| `GET·POST /api/work-orders` | 목록·생성, `PATCH /[id]` 완료/취소 |
| `POST /api/complaints/[id]/convert` | 민원 → 의뢰 전환(complaintId 연결, 민원 IN_PROGRESS). T2.6 스레드의 전환 버튼 활성화 |

**push 추천 발송** ([D4](../DECISIONS.md#-d4-마스터-매칭-방식--pull--push-하이브리드)): 의뢰 생성(두 경로 모두) 직후, 업종 일치 + 의뢰 위치가 활동반경 안 + `plan=PRO` 인 마스터를 거리순 최대 10명 골라 `WorkOrderTarget` 생성 + `MessageLog(WORK_ORDER_REQUEST)` 기록. 매칭 로직은 T3.6(중개 반경 매칭)의 거리 계산 유틸을 재사용한다. 모델 정의는 [T5.2](./t5.2-master-feed.md) 참조.

- **완료 기준**
  - [ ] 직접 생성·민원 전환 두 경로 완주, 전환 의뢰에 민원 링크 표시
  - [ ] 생성 시 PRO 마스터에게 `WorkOrderTarget` + 발송 로그 생성, FREE 마스터에게는 생성되지 않음
- **테스트** — 최소: 이미 전환된 민원 409(complaintId unique) · 전환 시 양쪽 상태 동기화 · push 타겟이 PRO·업종·반경 조건을 모두 만족하는 마스터에게만 생성
