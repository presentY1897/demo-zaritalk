## 배포에서 걸린 것 세 가지 (기록 — 전부 같은 부류)

셋 다 **"산출물·설정이 조용히 비어 있는데 에러 메시지는 엉뚱한 곳을 가리키는"** 유형이었다.

### 1. CI `test` job 이 코드젠을 안 돌림

`Cannot find module './generated/client'`. `packages/db/src/generated`(prisma client)와 `styled-system/`(panda)은 gitignore 된 코드젠 산출물인데, `check` job 의 `pnpm build` 결과는 다른 job 으로 전달되지 않는다. → 루트 `pnpm codegen` 을 test job 앞에 추가.

### 2. turbo 캐시가 prisma 산출물을 복원하지 않음

Vercel 빌드가 `The export ProfileType was not found in @zari/db` 로 실패. `@zari/db#build`(prisma generate)에 **outputs 선언이 없어** 캐시 히트 시 `src/generated` 가 복원되지 않았다. **첫 배포는 캐시가 비어 통과하고 두 번째부터 깨져서** Ready·Error 가 번갈아 나왔다. 로컬에서 계속 뜨던 `WARNING no output files found for task @zari/db#build` 가 이 신호였다.
→ `packages/db/turbo.json` 신설(`outputs: ["src/generated/**"]`), 루트 build outputs 에 `styled-system/**` 추가.

### 3. Vercel 환경변수 값에 따옴표

`/api/health` 가 `target: "(파싱 불가)"` + `Can't reach database server at base` 로 잡아냈다. `base` 는 pg 가 **연결 문자열 파싱에 실패했을 때의 폴백 호스트**다. Value 칸에 `DATABASE_URL="postgresql://…"` 를 통째로(또는 따옴표째) 넣으면 재현된다 — `.env` 일괄 붙여넣기 영역용 형식을 Value 칸에 넣은 경우.
→ 값은 **순수 연결 문자열만**. 세 형태의 파싱 결과는 [DEPLOY.md](../DEPLOY.md#apihealth-로-원인-구분하기) 참조.

> **교훈**: DB 라우트가 빈 500 만 내면 밖에서 원인을 못 가른다. `/api/health` 가 3번을 한 번에 짚었다.
