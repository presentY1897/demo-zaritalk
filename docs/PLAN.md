## 피드백 대기

답을 받으면 이 섹션에 결론을 기록하고 해당 [제안] 표시를 확정으로 바꾼다.

1. **Phase 순서** — 임대인 코어(1) → 세입자 결제(2) → 매물·중개(3) 순. 포트폴리오 임팩트 기준으로 지도·통근시간을 앞당기는 선택지도 있음.
2. **배포를 Phase 0으로** — 처음부터 라이브 주소 유지 vs 어느 정도 만들고 올리기.
3. **스펙 안의 [제안] 항목 확정**
   - API 스타일 — REST Route Handlers 통일(Server Actions 미사용)
   - A/B 실험 소재 — 공개 고지서의 가입 CTA(`notice_cta`)
   - 서류 업로드 저장소 — Vercel Blob
   - 마스터 매칭 — push 타겟팅이 아닌 pull 피드 방식
   - 웹 셸 — 최대폭 480px + 프로필별 하단 탭바 구성
4. **페이지 구성·기능 가감** — 특히 임대인 홈 대시보드([§2](./specs/02-lease.md)), 고지서 공개 페이지([§4](./specs/04-notice.md)), 매물 탐색 UX([§7](./specs/07-listing-commute.md))가 실물 앱과 크게 어긋나는지.
5. **백오피스 병행 방식** — 기능별 세트 구현 vs 별도 Phase로 몰아서.
6. **UI 톤** — 자리톡 실제 앱의 옐로 브랜드 톤 참고 vs 독자적 디자인. 참고 캡처 제공 시 정확도 상승.
